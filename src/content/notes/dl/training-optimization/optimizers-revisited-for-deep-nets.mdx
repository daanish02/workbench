[Gradient Descent Variants](../../../math/optimization/gradient-descent-variants/) introduced momentum, RMSProp and Adam on two-variable functions, and [Stochastic Gradient Descent](../../../math/optimization/stochastic-gradient-descent/) explained why noisy mini-batch gradients work. A deep network adds three practical concerns: the optimizer is applied to dozens of parameter tensors at once, it keeps state for every one of them, and that state costs as much memory as the model. This note implements SGD with momentum and Adam the way frameworks do, compares them on a real network, shows why Adam's bias correction matters, counts the memory, and explains why AdamW replaced Adam. The gradients come from [Backpropagation Derived](../../nn-foundations/backpropagation-fully-derived/); run the code with `uv run --with numpy`.

## Optimizers as objects

Every framework separates the model from the optimizer. The model computes gradients; the **optimizer** holds a reference to every parameter tensor, keeps **state** for each one, and on `step()` updates the tensors in place. The updates themselves are the formulas from the math note:

$$
\text{momentum: } v \leftarrow \mu v + g, \quad \theta \leftarrow \theta - \eta v; \qquad \text{Adam: } \theta \leftarrow \theta - \eta \frac{\hat m}{\sqrt{\hat s} + \epsilon}.

$$

In words: momentum keeps a velocity $v$ per parameter, a decaying sum of past gradients $g$, and steps along it. Adam keeps a running mean $m$ of the gradient and a running mean $s$ of its square, and steps along the mean divided by the root mean square, so every parameter's step has a size near the learning rate $\eta$ whatever the scale of its gradients. $\hat m$ and $\hat s$ are bias-corrected versions, explained below.

```python
import numpy as np

class SGD:
    def __init__(self, params, lr, momentum=0.0):
        self.params, self.lr, self.mu = params, lr, momentum
        self.v = [np.zeros_like(p) for p in params]   # one buffer per parameter
    def step(self, grads):
        for p, g, v in zip(self.params, grads, self.v):
            v *= self.mu
            v += g
            p -= self.lr * v                          # in place: p is the model's array

class Adam:
    def __init__(self, params, lr, betas=(0.9, 0.999), eps=1e-8, weight_decay=0.0):
        self.params, self.lr, self.b1, self.b2 = params, lr, *betas
        self.eps, self.wd, self.t = eps, weight_decay, 0
        self.m = [np.zeros_like(p) for p in params]   # running mean of g
        self.s = [np.zeros_like(p) for p in params]   # running mean of g^2
    def step(self, grads):
        self.t += 1
        for p, g, m, s in zip(self.params, grads, self.m, self.s):
            m += (1 - self.b1) * (g - m)
            s += (1 - self.b2) * (g * g - s)
            m_hat = m / (1 - self.b1 ** self.t)       # undo the bias towards 0
            s_hat = s / (1 - self.b2 ** self.t)
            p -= self.lr * (m_hat / (np.sqrt(s_hat) + self.eps) + self.wd * p)  # AdamW decay

def moons(rng):
    t = rng.uniform(0, np.pi, 200)
    X = np.vstack([np.c_[np.cos(t[:100]), np.sin(t[:100])],
                   np.c_[1 - np.cos(t[100:]), 0.5 - np.sin(t[100:])]])
    return X + rng.normal(scale=0.2, size=X.shape), np.r_[np.zeros(100, int), np.ones(100, int)]

def run(make_opt, steps=300):
    rng = np.random.default_rng(0)
    X, y = moons(rng)
    Y = np.eye(2)[y]
    W1, b1 = rng.normal(size=(2, 32)), np.zeros(32)
    W2, b2 = rng.normal(size=(32, 2)) * 0.01, np.zeros(2)
    opt = make_opt([W1, b1, W2, b2])
    for _ in range(steps):
        Z1 = X @ W1 + b1
        A1 = np.maximum(Z1, 0)
        Z2 = A1 @ W2 + b2
        P = np.exp(Z2 - Z2.max(1, keepdims=True))
        P /= P.sum(1, keepdims=True)
        dZ2 = (P - Y) / len(X)
        dZ1 = dZ2 @ W2.T * (Z1 > 0)
        opt.step([X.T @ dZ1, dZ1.sum(0), A1.T @ dZ2, dZ2.sum(0)])
    return -np.mean(np.log(P[np.arange(len(y)), y]))

print(f"SGD lr 0.1           loss {run(lambda p: SGD(p, 0.1)):.3f}")
print(f"SGD+momentum lr 0.1  loss {run(lambda p: SGD(p, 0.1, momentum=0.9)):.3f}")
print(f"Adam lr 0.01         loss {run(lambda p: Adam(p, 0.01)):.3f}")
# SGD lr 0.1           loss 0.282
# SGD+momentum lr 0.1  loss 0.112
# Adam lr 0.01         loss 0.099
```

In words: the same 32-unit network, data and initial weights, trained for 300 full-batch steps. Plain SGD gets the loss to 0.282, momentum to 0.112 and Adam to 0.099. The optimizers never see the network: they receive a list of arrays and a matching list of gradients, and update the arrays in place, which is exactly how `torch.optim` works with `model.parameters()`. Adam needed a learning rate ten times smaller, because its steps are normalised to roughly $\eta$ per parameter while SGD's scale with the gradient.

The interface has practical consequences. **Parameter groups** let one optimizer use different settings for different tensors, typically no weight decay on biases and normalization parameters. The state is saved with the model in checkpoints (`optimizer.state_dict()`); resuming training without it restarts Adam's moments from zero and causes a visible bump in the loss.

## Adam's bias correction

Adam initialises $m$ and $s$ at 0. Early on, the running averages are pulled towards that 0: after $t$ steps of a constant gradient $g$, $m_t = (1 - \beta_1^{t}) g$ and $s_t = (1 - \beta_2^{t}) g^{2}$. Dividing by $1 - \beta^{t}$ removes this bias exactly.

```python
b1, b2 = 0.9, 0.999
g = 0.5  # pretend the gradient is constant
m = s = 0.0
for t in range(1, 6):
    m = b1 * m + (1 - b1) * g
    s = b2 * s + (1 - b2) * g * g
    raw = m / s**0.5
    fixed = (m / (1 - b1**t)) / (s / (1 - b2**t)) ** 0.5
    print(f"step {t}: m {m:.4f}  raw step {raw:.3f}  bias-corrected step {fixed:.3f}")
# step 1: m 0.0500  raw step 3.162  bias-corrected step 1.000
# step 2: m 0.0950  raw step 4.250  bias-corrected step 1.000
# step 3: m 0.1355  raw step 4.950  bias-corrected step 1.000
# step 4: m 0.1719  raw step 5.442  bias-corrected step 1.000
# step 5: m 0.2048  raw step 5.797  bias-corrected step 1.000
```

In words: with a constant gradient the ideal normalised step is exactly 1 (times $\eta$). Without correction the first step is 3.162 and the step keeps growing, to 5.797 by step 5, because $s$ with $\beta_2 = 0.999$ warms up far more slowly than $m$. The raw ratio $(1 - \beta_1^{t}) / \sqrt{1 - \beta_2^{t}}$ peaks at 6.57 at step 12 and is still 1.26 at step 1000. With correction every step is 1.000. The bias correction is not a detail: without it the start of training takes steps several times larger than the learning rate says.

## The memory bill

Each piece of per-parameter state is a full copy of the model's size.

```python
params = 7e9
bytes_per = {
    "SGD": 4 + 4,                 # fp32 weights + gradients
    "SGD + momentum": 4 + 4 + 4,  # + velocity
    "Adam / AdamW": 4 + 4 + 4 + 4,  # + first and second moments
}
for name, b in bytes_per.items():
    print(f"{name:15s} {b:2d} bytes/param -> {params * b / 2**30:6.1f} GiB for 7B parameters")
# SGD              8 bytes/param ->   52.2 GiB for 7B parameters
# SGD + momentum  12 bytes/param ->   78.2 GiB for 7B parameters
# Adam / AdamW    16 bytes/param ->  104.3 GiB for 7B parameters
```

In words: training a 7-billion-parameter model with Adam in fp32 needs 104.3 GiB just for weights, gradients and the two moments, before a single activation is stored, more than one 80 GB GPU holds. That is why large-model training shards optimizer state across GPUs (ZeRO, FSDP) and why memory-light optimizers such as Adafactor, which stores factored second moments, and 8-bit Adam exist. Mixed-precision training keeps the same 16 bytes per parameter in a different split: 2-byte weights and gradients plus a 4-byte master copy and the two 4-byte moments.

## AdamW and weight decay

**Weight decay** shrinks every weight a little each step, $\theta \leftarrow \theta - \eta \lambda \theta$. For plain SGD that is identical to adding an L2 penalty $\tfrac{\lambda}{2} \lVert \theta \rVert^{2}$ to the loss, so libraries implemented weight decay by adding $\lambda \theta$ to the gradient. Under Adam the two are not the same: the added $\lambda \theta$ is divided by $\sqrt{\hat s}$ like the rest of the gradient, so parameters with large gradients are barely decayed. **AdamW** decouples them and subtracts $\eta \lambda \theta$ outside the normalisation.

```python
import numpy as np

# two weights with the same value: one gets big, noisy gradients, one small ones
w_l2 = np.array([1.0, 1.0])
w_dec = np.array([1.0, 1.0])
lr, lam, b2, eps = 0.01, 0.1, 0.999, 1e-8
rng = np.random.default_rng(0)
s_l2 = np.zeros(2)
s_dec = np.zeros(2)
for t in range(1, 1001):
    g = rng.normal(size=2) * np.array([10.0, 0.1])   # pure noise, mean zero
    g_l2 = g + lam * w_l2                            # L2 penalty folded into the gradient
    s_l2 = b2 * s_l2 + (1 - b2) * g_l2**2
    w_l2 -= lr * g_l2 / (np.sqrt(s_l2 / (1 - b2**t)) + eps)
    s_dec = b2 * s_dec + (1 - b2) * g**2
    w_dec -= lr * (g / (np.sqrt(s_dec / (1 - b2**t)) + eps) + lam * w_dec)  # decoupled
print("Adam + L2 (noisy, quiet):", np.round(w_l2, 3))
print("AdamW     (noisy, quiet):", np.round(w_dec, 3))
# Adam + L2 (noisy, quiet): [1.166 0.068]
# AdamW     (noisy, quiet): [0.503 0.61 ]
```

In words: both weights start at 1 and receive only zero-mean noise, so the decay is the only systematic force. With the L2 term inside Adam, the weight with gradient noise of scale 10 is hardly decayed and wanders to 1.166, while the quiet one with noise 0.1 is crushed to 0.068: the same $\lambda$ regularizes them a hundredfold differently. With AdamW both shrink by a similar amount, to 0.503 and 0.61, as weight decay is meant to. (The momentum term is left out to keep the comparison to the second moment, which is where the difference comes from.)

<Callout type="pitfall">
`torch.optim.Adam(..., weight_decay=λ)` is Adam with an L2 term, not AdamW. For transformers and most modern training use `torch.optim.AdamW`, and put biases and normalization weights in a parameter group with `weight_decay=0`. Typical values are $\lambda$ = 0.01 to 0.1, far larger than the 1e-4 to 5e-4 used with SGD, because AdamW multiplies it by the learning rate.
</Callout>

## Choosing in practice

| Setting | Common default |
|---|---|
| Transformers, LLMs, most new work | AdamW, $\beta = (0.9, 0.95$ to $0.999)$, $\epsilon = 10^{-8}$, with warmup and decay |
| CNNs on images (ResNet-style) | SGD with momentum 0.9 and weight decay $5 \times 10^{-4}$, or AdamW |
| Memory-limited large models | Adafactor or 8-bit AdamW, or sharded state |

Adam is the less sensitive starting point: its per-parameter scaling copes with gradients of very different sizes across layers. Well-tuned SGD with momentum still sometimes generalizes slightly better on image classification. Whatever the optimizer, the learning rate and its schedule matter more than the choice between them; see [Learning Rate Schedules](../learning-rate-schedules/).

<Callout type="key">
An optimizer is per-parameter state plus an in-place update. Adam's state doubles the memory of the model, its bias correction keeps early steps honest, and weight decay belongs outside its normalisation, which is what AdamW does.
</Callout>

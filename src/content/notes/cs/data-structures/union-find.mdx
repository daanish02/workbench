Some questions about a [graph](../graphs/) are only about connection: are these two computers on the same network, do these two accounts belong to the same person, does this new edge close a cycle? A breadth-first search answers one such question in $O(V + E)$, but when edges keep arriving and the question keeps being asked, that is too slow. **Union-find**, also called a **disjoint-set** data structure, keeps a partition of elements into groups and supports merging groups and asking for an element's group in nearly constant time. This note builds it from a plain parent array, adds the two optimizations that make it fast, and applies it to Kruskal's algorithm from [Greedy Algorithms](../../algorithms/greedy-algorithms/).

## Groups as Trees

The structure maintains a collection of **disjoint sets**: every element belongs to exactly one. It supports two operations:

- **find(x)**: return a representative of the set containing `x`. Two elements are in the same set exactly when their representatives are equal.
- **union(a, b)**: merge the set containing `a` with the set containing `b`.

The representation is a forest stored in one array: `parent[x]` is `x`'s parent, and a **root** is an element that is its own parent. Each tree is one set, and its root is the representative. Initially every element is a root of a one-element tree. `find` follows parent pointers up to the root; `union` finds both roots and makes one the parent of the other.

Without care, the trees can degenerate into chains: union `0` with `1`, then the result with `2`, and so on, always linking the old root under the new element, and `find(0)` has to walk the whole chain. The two fixes below prevent that.

## Union by Rank

**Union by rank** keeps trees shallow. Each root stores a **rank**, an upper bound on its tree's height. When linking two roots, the one with the smaller rank goes under the larger; only when the ranks are equal does the height grow, and then the new root's rank goes up by one. A tree of rank $r$ therefore contains at least $2^{r}$ elements, so no tree is taller than $\log_2 n$. (**Union by size**, which links the smaller set under the larger, gives the same bound.)

```python
def height_after_chain(n, by_rank):
    parent, rank = list(range(n)), [0] * n
    def find(x):                               # no path compression, to isolate the effect of ranks
        while parent[x] != x:
            x = parent[x]
        return x
    for i in range(1, n):                      # union(0,1), union(0,2), ...: the worst order for naive linking
        ra, rb = find(i), find(0)
        if by_rank and rank[ra] < rank[rb]:
            ra, rb = rb, ra
        parent[rb] = ra
        if rank[ra] == rank[rb]:
            rank[ra] += 1
    def depth(x):
        d = 0
        while parent[x] != x:
            x, d = parent[x], d + 1
        return d
    return max(depth(x) for x in range(n))

for n in (16, 1024):
    print(f"n={n}: naive height={height_after_chain(n, False)}, by rank={height_after_chain(n, True)}")
# n=16: naive height=15, by rank=1
# n=1024: naive height=1023, by rank=1
```

In words: always hanging the existing tree under the new element builds a chain of height $n - 1$ (15 for 16 elements, 1023 for 1024), so `find` on the deepest element costs $O(n)$. With ranks, the big tree's root keeps its place and every new element hangs directly beneath it, so the height stays at 1. Even in the worst order for ranked unions (merging equal-sized trees each time) the height is at most $\log_2 n$, which is 10 for 1024 elements.

## Path Compression

**Path compression** makes every `find` repair the tree it walks. After locating the root, it sets the parent of every node on the path directly to the root, so the next `find` on any of them takes one step. The full structure:

```python
class UnionFind:
    def __init__(self, n):
        self.parent = list(range(n))           # every element starts as its own root
        self.rank = [0] * n                    # upper bound on tree height

    def find(self, x):
        root = x
        while self.parent[root] != root:
            root = self.parent[root]
        while self.parent[x] != root:          # path compression: point every node on the path at the root
            self.parent[x], x = root, self.parent[x]
        return root

    def union(self, a, b):
        ra, rb = self.find(a), self.find(b)
        if ra == rb:
            return False                       # already in the same set
        if self.rank[ra] < self.rank[rb]:      # union by rank: hang the shorter tree under the taller one
            ra, rb = rb, ra
        self.parent[rb] = ra
        if self.rank[ra] == self.rank[rb]:
            self.rank[ra] += 1
        return True

uf = UnionFind(8)
for a, b in [(0, 1), (2, 3), (1, 3), (5, 6)]:
    uf.union(a, b)
print("0 and 2 connected:", uf.find(0) == uf.find(2))
print("0 and 5 connected:", uf.find(0) == uf.find(5))
print("union(1, 2) merged anything:", uf.union(1, 2))
groups = {}
for x in range(8):
    groups.setdefault(uf.find(x), []).append(x)
print("sets:", sorted(groups.values()))
# 0 and 2 connected: True
# 0 and 5 connected: False
# union(1, 2) merged anything: False
# sets: [[0, 1, 2, 3], [4], [5, 6], [7]]
```

In words: after the unions `0–1`, `2–3`, `1–3` and `5–6`, elements 0 and 2 share a root (via `1–3`), while 0 and 5 do not. `union(1, 2)` returns `False` because 1 and 2 are already in one set; that return value is how Kruskal's algorithm and cycle detection use the structure. The 8 elements end up in 4 sets: `{0, 1, 2, 3}`, `{4}`, `{5, 6}` and `{7}`. Step through unions and finds, and switch the optimizations off to see the trees grow tall:

## Nearly Constant Time

With union by rank alone, each operation costs $O(\log n)$. With path compression added, Tarjan proved that any sequence of $m$ operations on $n$ elements costs

$$
O\big(m \, \alpha(n)\big),

$$

where $\alpha$ is the **inverse Ackermann function**. In words: $\alpha(n)$ grows so slowly that it is at most 4 for every $n$ that could fit in any computer (it first reaches 5 at a number with far more digits than there are atoms in the universe), so each operation is constant time in practice. The bound is **amortized** (averaged over the sequence): a single `find` can still walk a long path, but it flattens that path for everyone afterwards.

<Callout type="pitfall">
Union-find only merges. It cannot **split** a set or delete an edge: once two elements are connected they stay connected. If edges are removed, either rebuild from scratch, process the operations in reverse (removals become unions), or use a dynamic-connectivity structure.
</Callout>

## Kruskal and Other Uses

**Kruskal's algorithm** builds a minimum spanning tree by taking edges from lightest to heaviest and keeping an edge only if its endpoints are in different components, which is exactly `union` returning `True`:

```python
parent = {}

def find(x):
    parent.setdefault(x, x)
    if parent[x] != x:
        parent[x] = find(parent[x])            # recursive path compression
    return parent[x]

def union(a, b):
    ra, rb = find(a), find(b)
    if ra == rb:
        return False
    parent[rb] = ra
    return True

edges = [(1, "A", "B"), (2, "B", "C"), (3, "A", "C"), (4, "C", "D"), (5, "B", "D"), (6, "D", "E")]
tree = [(w, a, b) for w, a, b in sorted(edges) if union(a, b)]   # Kruskal: keep an edge only if it joins two sets
print("MST edges:", tree)
print("total weight:", sum(w for w, _, _ in tree))

import networkx as nx                          # cross-check with a library MST
G = nx.Graph()
G.add_weighted_edges_from((a, b, w) for w, a, b in edges)
print("networkx agrees:", nx.minimum_spanning_tree(G).size(weight="weight") == sum(w for w, _, _ in tree))
# MST edges: [(1, 'A', 'B'), (2, 'B', 'C'), (4, 'C', 'D'), (6, 'D', 'E')]
# total weight: 13
# networkx agrees: True
```

In words: edges of weight 3 (`A–C`) and 5 (`B–D`) are rejected because their endpoints were already connected, so adding them would close a cycle. The tree keeps 4 edges for 5 vertices with total weight 13, and networkx's minimum spanning tree has the same weight. Sorting dominates: $O(E \log E)$, with the union-find work nearly linear on top. Run it with `uv run --with networkx`.

Other common uses:

- **Connected components** of a graph that arrives as a stream of edges, or of a pixel grid (labelling regions in an image).
- **Cycle detection** in an undirected graph: an edge whose endpoints already share a root closes a cycle.
- **Grouping equivalent items**: merging user accounts that share an email, unifying type variables in a compiler's type inference, or clustering points whose distance is below a threshold.
- **Percolation** and network reliability simulations, where sites open one by one and the question is when two sides connect.

<Callout type="key">
Reach for union-find when the question is "are these two connected?" and connections are only ever added. For paths, distances or deletions, use a graph search or a richer structure.
</Callout>

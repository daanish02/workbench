A **blockchain** is a specific, unusual answer to the [consensus](../consensus/) problem: how can thousands of mutually distrusting machines, with no leader and no known membership, agree on a single ordered history of transactions? Classic protocols such as Raft assume a fixed, known group of nodes that are not malicious. Blockchains drop both assumptions and pay for it in speed and energy. It is worth understanding both as an idea and as a trade-off, even if you never build one.

## A Hash-Linked Log

The data structure is simple. Transactions are grouped into **blocks**. Each block records:

- the transactions,
- the **hash of the previous block**,
- a number used for the proof of work (the **nonce**).

A block's hash covers all of that, including the previous hash. So altering any old transaction changes that block's hash, which no longer matches the "previous hash" stored in the next block, which breaks the link, and so on to the end of the chain. Tampering is therefore **detectable** by anyone who recomputes the hashes. (This is the same idea as the commit chain in [Git Internals](../../software-engineering/git-internals/).)

## Proof of Work: Making Writes Costly

Hash links alone prove tampering, but do not stop someone from rebuilding the whole chain with new hashes. **Proof of work** (PoW) makes that expensive: a block counts only if its hash is below a target, such as beginning with a number of zero digits. Since a hash is unpredictable, the only way to find one is to try nonces until you get lucky. This is called **mining**.

```python
import hashlib
import json


def h(block):
    return hashlib.sha256(json.dumps(block, sort_keys=True).encode()).hexdigest()


def mine(prev, data, difficulty=4):
    nonce = 0
    while True:
        b = {"prev": prev, "data": data, "nonce": nonce}
        if h(b).startswith("0" * difficulty):          # proof of work: brute-force a hash with leading zeros
            return b
        nonce += 1


chain = [mine("0" * 64, "genesis")]
for tx in ("alice->bob 5", "bob->carol 2"):
    chain.append(mine(h(chain[-1]), tx))


def valid(c):
    return all(c[i]["prev"] == h(c[i - 1]) and h(c[i]).startswith("0000") for i in range(1, len(c)))


print("nonces:", [b["nonce"] for b in chain], "valid:", valid(chain))
chain[1]["data"] = "alice->bob 500"                   # tamper with history
print("after tampering, valid:", valid(chain))
# nonces: [6610, 10320, 14191] valid: True
# after tampering, valid: False
```

Finding a block takes thousands of attempts; **checking** one takes a single hash. That asymmetry is the heart of the scheme: work is expensive to do and cheap to verify. Each extra required zero digit multiplies the expected work by 16 (with hexadecimal digits).

## Agreeing Without a Leader: The Longest Chain

Everyone can mine, so two miners may find valid blocks at about the same time, creating a **fork**: two competing versions of the next block. The rule resolves it:

> Nodes always adopt the valid chain with the most accumulated work (informally, the longest), and keep mining on top of it.

Within a short time one branch gets extended first; nodes switch to it and the other is abandoned (**orphaned**). Nobody is elected: the network converges because mining power flows to whichever chain is currently winning.

This gives **probabilistic finality**. A transaction in the newest block can still be reversed if a competing chain overtakes. Each further block built on top makes reversal exponentially less likely, which is why exchanges wait several confirmations (about six on Bitcoin) before treating a payment as final. Contrast this with Raft, where a committed entry is final immediately.

<Callout type="key">
**Security comes from cost.** To rewrite history, an attacker must redo the proof of work for the altered block and every block after it, faster than the honest network adds new ones. Controlling over half of the network's mining power makes that possible (a **51% attack**); below that it is increasingly unlikely.
</Callout>

## Alternatives and Variants

- **Proof of stake (PoS).** Validators lock up their own cryptocurrency as collateral and are chosen to propose and vote on blocks; cheating forfeits the stake. It replaces energy cost with financial cost and is used by Ethereum. Many PoS designs finish with BFT-style voting that gives **deterministic finality**.
- **BFT protocols (PBFT, Tendermint).** For known, permissioned groups: nodes vote in rounds and tolerate up to $f$ Byzantine nodes out of $3f+1$ (see [Fault Tolerance](../fault-tolerance/)). Fast, final, but costly in messages and limited to tens or hundreds of nodes.
- **Permissioned ledgers.** Business consortia that want a shared log among a few known parties often use these, or simply a replicated database.

## Costs, and When It Fits

| Property | Classic consensus (Raft/Paxos) | Proof-of-work blockchain |
| --- | --- | --- |
| **Participants** | Known, trusted | Anonymous, untrusted |
| **Fault model** | Crash faults | Byzantine (anyone may cheat) |
| **Throughput** | Thousands to hundreds of thousands tx/s | Single digits to tens tx/s |
| **Finality** | Immediate | Probabilistic, minutes |
| **Energy** | Negligible | Very large (PoW) |

<Callout type="pitfall">
"Blockchain" is often proposed where an ordinary database would do. If a single organisation, or a group that trusts a common operator, controls the data, a replicated database with [consensus](../consensus/) is faster, cheaper and simpler. Blockchains earn their cost only when participants distrust each other and no one can be trusted to run the ledger.
</Callout>

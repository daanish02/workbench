Most servers, containers and cloud machines run Linux, and you operate them through a text interface called the **shell** (usually `bash`). This note covers the few ideas that make the whole toolbox make sense, followed by a cheat sheet you can search. For the system underneath, see [Kernel Architecture](../../operating-systems/kernel-architecture/) and [System Calls](../../operating-systems/system-calls/).

## How the Shell Works

When you type a command the shell **finds a program** (searching the directories in your `PATH`), **starts it as a process** with your arguments, and waits. Three ideas explain almost everything else.

**Streams.** Every process has three standard channels: **stdin** (input, normally the keyboard), **stdout** (normal output, the screen) and **stderr** (error messages, also the screen). Redirection rewires them: `>` writes stdout to a file, `>>` appends, `<` reads stdin from a file, and `2>&1` sends errors to the same place as normal output.

**Pipes.** `a | b` connects the stdout of `a` to the stdin of `b`. Each tool does one small job on a stream of text, and a pipeline chains them. For example, given an access log, count requests per path, then list the paths that produced errors:

```bash
$ cat access.log
GET /home 200
GET /cart 200
POST /pay 500
GET /home 200
GET /home 404
POST /pay 200

$ cut -d' ' -f2 access.log | sort | uniq -c | sort -rn     # path, count, most common first
      3 /home
      2 /pay
      1 /cart

$ awk '$3 >= 400 {print $2}' access.log | sort -u          # paths with a status of 400 or more
/home
/pay
```

In words: `cut` takes the second column, `sort` groups equal lines together, `uniq -c` counts runs of equal lines, and the final `sort -rn` orders by that count. None of these programs knows about the others; the pipe is the glue.

**Exit codes.** When a command finishes it returns a number: `0` for success and non-zero for failure. The shell keeps the last one in `$?`. `a && b` runs `b` only if `a` succeeded, and `a || b` runs `b` only if `a` failed, which is how scripts chain steps and stop on errors.

**Permissions.** Each file has an owner, a group and everyone else ("other"), and each of the three gets read (`r`, 4), write (`w`, 2) and execute (`x`, 1) rights. Add the numbers for each class: `chmod 755 run.sh` means owner `7` (read, write, execute), group `5` (read, execute), other `5` (read, execute). `chmod 640` is owner read and write, group read, other nothing, which is typical for a private config file.

<Callout type="pitfall">
The shell does exactly what you type, with no undo. `rm -rf` deletes without asking or using a trash bin, and a stray space in `rm -rf /tmp/build /` is a disaster. Read destructive commands twice, run `ls` with the same pattern first, and be careful with `sudo`, which runs a command with administrator rights.
</Callout>

### Files and Directories

| Command | What it does | Example |
| --- | --- | --- |
| `pwd` | Print the current directory | `pwd` |
| `ls` | List files (`-l` details, `-a` hidden, `-h` readable sizes) | `ls -lah` |
| `cd` | Change directory (`cd -` goes back, `cd` alone goes home) | `cd /var/log` |
| `mkdir` | Make a directory (`-p` creates parents too) | `mkdir -p app/src/utils` |
| `cp` | Copy files (`-r` for directories) | `cp -r src backup` |
| `mv` | Move or rename | `mv old.txt new.txt` |
| `rm` | Delete files (`-r` directories, `-f` no prompt; permanent) | `rm -r build` |
| `touch` | Create an empty file or update its timestamp | `touch notes.txt` |
| `ln -s` | Create a symbolic link (a shortcut) | `ln -s /opt/app/current app` |
| `find` | Search for files by name, type, size or age | `find . -name "*.log" -mtime -1` |
| `stat` | Show detailed file information | `stat app.py` |
| `file` | Guess what kind of file something is | `file mystery.bin` |

### Viewing and Searching Text

| Command | What it does | Example |
| --- | --- | --- |
| `cat` | Print a file to the screen | `cat config.yml` |
| `less` | Page through a file (`/` to search, `q` to quit) | `less server.log` |
| `head` / `tail` | First or last lines (`tail -f` follows new lines live) | `tail -f app.log` |
| `wc` | Count lines, words, bytes (`-l` lines) | `wc -l access.log` |
| `grep` | Print lines matching a pattern (`-i` ignore case, `-r` recurse, `-n` line numbers, `-v` invert) | `grep -rn "TODO" src` |
| `sed` | Stream editor, mostly for substitution | `sed 's/http:/https:/g' urls.txt` |
| `awk` | Process text by column | `awk '{print $1, $3}' data.txt` |
| `cut` | Pick columns by delimiter | `cut -d, -f1,3 data.csv` |
| `sort` | Sort lines (`-n` numeric, `-r` reverse, `-u` unique) | `sort -n sizes.txt` |
| `uniq` | Collapse adjacent duplicates (`-c` count; sort first) | `sort ips.txt \| uniq -c` |
| `tr` | Translate or delete characters | `tr 'a-z' 'A-Z' < in.txt` |
| `xargs` | Turn input lines into arguments for a command | `find . -name "*.tmp" \| xargs rm` |
| `tee` | Write to a file and to the screen at once | `make 2>&1 \| tee build.log` |
| `diff` | Compare two files | `diff -u old.txt new.txt` |
| `jq` | Query and reshape JSON (a separate package) | `curl -s api.example.com \| jq '.items[0]'` |

| `journalctl` | Read logs managed by systemd | `journalctl -u nginx --since "1 hour ago"` |

| `time` | Measure how long a command takes | `time python solve.py` |

## Reading a Command

Every command has the same shape: `program [options] [arguments]`. Options (`-l`, `--help`) change behaviour; arguments say what to act on. Short options combine, so `ls -l -a -h` is `ls -lah`. When you meet an unfamiliar command, try `command --help` for a summary, `man command` for the full manual, or paste it into [explainshell](https://explainshell.com/) to see each piece explained. The commands for [Git](../../software-engineering/git-internals/) and for [containers](../../software-engineering/containerization/) follow the same pattern, so once this shape is familiar most command-line tools are readable.

Some files should not be committed or copied into an image: dependency folders a package manager recreates, build output, caches, logs, editor settings, and above all secrets such as `.env`. **Ignore files** list patterns that a tool skips. Git reads `.gitignore`; `docker build` reads `.dockerignore`. This sheet lists what to ignore, explains the wildcards so you can write your own rules, and flags where the two files differ. It builds on [Git & GitHub](../git-cheat-sheet/) and the [Docker Sheet](../docker-sheet/).

## What To Ignore

Type to filter by language, tool or purpose (for example "python", "secret" or "cache"). Each row gives the pattern for both files; `**/` in the Docker column is needed because Docker patterns match from the context root only (see [Differences That Bite](#differences-that-bite)). A dash means the file has no use for that row.

<FilterTable placeholder="Filter, e.g. python, node, secret, cache, java">

### Secrets and Local Config

| What | `.gitignore` | `.dockerignore` | Why |
| --- | --- | --- | --- |
| Environment files | `.env`, `.env.*`, `!.env.example` | `**/.env`, `**/.env.*`, `!**/.env.example` | Hold keys and passwords. Commit the `.example` file so others see the variable names |
| Private keys and certificates | `*.pem`, `*.key` | `**/*.pem`, `**/*.key` | A key in an image layer or in history is compromised |
| Local overrides | `*.local`, `local.*` | `**/*.local`, `**/local.*` | Per-machine settings |
| Terraform state and variables | `*.tfstate*`, `.terraform/`, `*.auto.tfvars` | `**/*.tfstate*`, `**/.terraform`, `**/*.auto.tfvars` | State files can contain secrets in plain text |

### Dependencies

| What | `.gitignore` | `.dockerignore` | Why |
| --- | --- | --- | --- |
| Node packages | `node_modules/` | `**/node_modules` | Recreated by `bun install`; host-built packages can break inside an image |
| Python environments | `.venv/`, `venv/` | `**/.venv`, `**/venv` | Recreated from the lock file; tied to the host operating system |
| Vendored code (PHP, Ruby, Go) | `vendor/` | `**/vendor` | Ignore only if the package manager restores it; keep it if you vendor on purpose |

### Build Output

| What | `.gitignore` | `.dockerignore` | Why |
| --- | --- | --- | --- |
| JavaScript and web builds | `dist/`, `build/`, `out/`, `.next/` | `**/dist`, `**/build`, `**/out`, `**/.next` | Generated from the source |
| Python packaging | `dist/`, `build/`, `*.egg-info/` | `**/dist`, `**/build`, `**/*.egg-info` | Generated by the build tool |
| Java and Kotlin | `target/` (Maven), `build/` (Gradle), `*.class` | `**/target`, `**/build`, `**/*.class` | Compiled output |
| Rust | `target/` | `**/target` | Compiled output; can reach gigabytes |
| C and C++ | `*.o`, `*.a`, `*.so`, `*.exe` | `**/*.o`, `**/*.a`, `**/*.so`, `**/*.exe` | Object files and binaries |
| .NET | `bin/`, `obj/` | `**/bin`, `**/obj` | Compiled output |

### Caches and Generated Files

| What | `.gitignore` | `.dockerignore` | Why |
| --- | --- | --- | --- |
| Python bytecode and tool caches | `__pycache__/`, `*.py[cod]`, `.pytest_cache/`, `.mypy_cache/`, `.ruff_cache/` | `**/__pycache__`, `**/*.pyc`, `**/.pytest_cache`, `**/.mypy_cache`, `**/.ruff_cache` | Rebuilt on every run |
| Test coverage | `coverage/`, `htmlcov/`, `.coverage` | `**/coverage`, `**/htmlcov`, `**/.coverage` | Generated reports |
| Jupyter checkpoints | `.ipynb_checkpoints/` | `**/.ipynb_checkpoints` | Autosave copies of notebooks |

### Logs and Data

| What | `.gitignore` | `.dockerignore` | Why |
| --- | --- | --- | --- |
| Logs | `*.log`, `logs/` | `**/*.log`, `**/logs` | Grow forever and change on every run |
| Temporary files | `*.tmp`, `tmp/` | `**/*.tmp`, `**/tmp` | Scratch output |
| Local databases | `*.sqlite`, `*.db` | `**/*.sqlite`, `**/*.db` | Local data, not source |
| A data folder you want to keep empty | `data/*`, `!data/.gitkeep` | `data/*` | Git does not track empty folders, so commit a placeholder file |

### Editors and Operating Systems

| What | `.gitignore` | `.dockerignore` | Why |
| --- | --- | --- | --- |
| macOS and Windows folder files | `.DS_Store`, `Thumbs.db` | `**/.DS_Store`, `**/Thumbs.db` | Created by the file manager |
| JetBrains and VS Code settings | `.idea/`, `.vscode/` | `**/.idea`, `**/.vscode` | Personal; some teams commit shared files such as `.vscode/settings.json` |
| Editor swap and backup files | `*.swp`, `*~` | `**/*.swp`, `**/*~` | Left by vim, emacs and others |

Personal rows (editors and operating systems) belong in your global ignore file rather than in every project: `git config --global core.excludesFile ~/.gitignore_global`.

### Only in .dockerignore

| What | `.gitignore` | `.dockerignore` | Why |
| --- | --- | --- | --- |
| Git history | — | `.git` | Large, and rarely needed in an image; also changes on every commit, which breaks the layer cache |
| CI and Git metadata | — | `.github`, `.gitignore` | Not used at run time |
| Docker files | — | `Dockerfile*`, `docker-compose*.yml` | Not needed inside the image; still sent to the builder, which needs them |
| Documentation | — | `*.md`, `!README.md` | Rarely needed at run time; some build tools read the README |

</FilterTable>

## Wildcards

The same few symbols write every custom rule. Where a row differs between the files, the difference is in the last two columns.

| Pattern | Matches | `.gitignore` | `.dockerignore` |
| --- | --- | --- | --- |
| `*` | Any run of characters, never across `/` | `*.log` | `*.log` |
| `?` | Exactly one character, never `/` | `debug?` | `debug?` |
| `**` | Any number of directories, including none | `**/logs`, `a/**/b` | `**/logs`, `a/**/b` |
| `!` at the start | Exception: re-include what an earlier line ignored. The last matching line wins | `!keep.log` | `!keep.log` |
| `#` at the start | Comment | yes | yes (column 1) |
| Leading `/` | Anchor to the folder holding the file | yes: `/build` is the root one only | ignored |
| Trailing `/` | Directories only | yes: `build/` | ignored |
| `\` | Escape a leading `#` or `!`, or a trailing space | yes | not documented |

`.gitignore` also accepts character sets, `[abc]` and `[a-z]`, as in `*.[oa]`.

## Writing Custom Patterns

| I want to ignore | `.gitignore` | `.dockerignore` |
| --- | --- | --- |
| A file type at every depth | `*.log` | `**/*.log` |
| A file type in the root only | `/*.log` | `*.log` |
| A folder at every depth | `cache/` | `**/cache` |
| A folder in the root only | `/cache/` | `cache` |
| A folder one level down only | `*/cache/` | `*/cache` |
| One file name at every depth | `secrets.json` | `**/secrets.json` |
| Everything in a folder, keep one file | `logs/*`, `!logs/.gitkeep` | `logs/*`, `!logs/.gitkeep` |
| All of a type except one file | `*.md`, `!README.md` | `*.md`, `!README.md` (root only) |

Read rules from top to bottom: for each path the **last matching line wins**, so an exception must come after the pattern it overrides. Test a new rule on one path before trusting it (see Checking and Fixing below).

## Differences That Bite

- **Depth**: a slash-free `.gitignore` pattern matches at any depth; a `.dockerignore` pattern matches from the context root only, so `node_modules` there ignores just the root folder. Use `**/` for every depth.
- **Exceptions under an ignored folder (Git)**: `build/` then `!build/keep.txt` does nothing, because Git never looks inside an ignored folder. Ignore the contents instead: `build/*` then `!build/keep.txt`.
- **Slashes**: in `.gitignore` a leading or middle slash anchors the pattern and a trailing slash means directories only; in `.dockerignore` leading and trailing slashes are disregarded, so `/build` and `build/` both mean `build`.
- **Locations**: Git reads a `.gitignore` in any folder, plus `.git/info/exclude` (this clone only) and the global file. Docker reads one `.dockerignore` in the context root. A file named `<Dockerfile name>.dockerignore` next to a Dockerfile (for example `build.Dockerfile.dockerignore`) takes precedence for builds that use that Dockerfile.

## A .gitignore to Start From

```text
# secrets and local config
.env
.env.*
!.env.example
*.pem
*.key

# dependencies
node_modules/
.venv/

# build output
dist/
build/
out/
target/
*.egg-info/

# caches and generated files
__pycache__/
*.py[cod]
.pytest_cache/
.mypy_cache/
.ruff_cache/
coverage/
.ipynb_checkpoints/

# logs and local data
*.log
*.tmp
data/*
!data/.gitkeep
```

In words: this is the tables above put together for a Python or Node project, with a comment for each group. `.env.*` followed by `!.env.example` ignores every environment file except the template, which works because both lines name files, not a folder. `data/*` with `!data/.gitkeep` keeps an empty folder in the repository. Editor and operating-system files are left out on purpose: put them in your global ignore file so every project does not repeat them. Trim to your stack, and add a custom line from the tables for anything else.

## A .dockerignore to Start From

```text
.git
.github
.gitignore
**/.env
**/.env.*
!**/.env.example
**/node_modules
**/.venv
**/__pycache__
**/dist
**/build
**/*.log
Dockerfile*
docker-compose*.yml
*.md
!README.md
```

In words: this is the earlier tables put together for a Python or Node service. Every pattern that should match in subfolders starts with `**/`; the ones for the root (`.git`, `*.md`) do not. The `!` lines come after the patterns they override. Trim it to your stack, and add a custom line from the tables above for anything else, such as `**/*.sqlite` or `**/.terraform`.

## Checking and Fixing

```bash
git check-ignore -v path/to/file          # which rule ignores this path
git status --ignored                      # list ignored files too
git ls-files -ci --exclude-standard       # tracked files that now match an ignore rule
git rm --cached path/to/file              # stop tracking a file, keep it on disk
git add -f path/to/file                   # track an ignored file anyway
git clean -ndX                            # preview deleting ignored files only (drop -n to delete)
```

In words: `check-ignore -v` answers "why is this ignored?" by printing the file, line and pattern. `ls-files -ci --exclude-standard` answers the opposite question, "what is tracked that I meant to ignore?", and its output is the list to give to `git rm --cached`. `git clean -X` (capital) deletes only ignored files, which clears build output without touching source; without `-n` the deletion is permanent. For Docker, the line near the start of a build that reports the size of the context is the quickest check: a number far larger than the source tree points to a missing `.dockerignore` rule.

<Callout type="pitfall">
Adding a path to `.gitignore` does not remove it if it was ever committed, and adding it to `.dockerignore` does not remove it from an image already built. Both files only affect what is skipped from now on. A secret that was committed or baked into an image layer is compromised: rotate it first, then clean the history (see "Recovering Lost Work" in [Git & GitHub](../git-cheat-sheet/)) or rebuild the image.
</Callout>

Some messages tell you more than others. Learning that a fair coin landed heads tells you one bit; learning that the sun rose tells you almost nothing. Shannon's entropy turns this into a number for a whole distribution: the average information you get from one outcome, measured in bits. It is the central quantity of information theory, and it sets the limit on how far data can be compressed. This note defines surprise and entropy, checks the fair and loaded coin, and connects entropy to the game of twenty questions.

## Surprise

An outcome with probability $p$ carries surprise $\log_2(1/p)$ bits. Using base 2 means the unit is the bit: one yes/no answer. A fair coin flip has $p = \frac{1}{2}$, so its surprise is exactly one bit. A one-in-eight event has surprise three bits.

```python
import math

for p in [1 / 2, 1 / 4, 1 / 8, 0.9]:
    print(f"p = {p:.3f}: surprise = {math.log2(1 / p):.3f} bits")  # prints: p = 0.500: surprise = 1.000 bits
```

In words: halving the probability adds one bit. The likely outcome $0.9$ carries only $0.152$ bits, which is why common news is cheap to report.

## Entropy as average surprise

The entropy averages surprise over the distribution:

$$
H(p) = -\sum_x p(x)\log_2 p(x).
$$

The script below computes it for a fair coin, a loaded coin and a fair eight-sided die.

```python
import math

def H(ps):
    return -sum(p * math.log2(p) for p in ps if p > 0)

print("fair coin:", round(H([0.5, 0.5]), 3), "bits")  # prints: fair coin: 1.0 bits
print("loaded coin (0.9, 0.1):", round(H([0.9, 0.1]), 3), "bits")  # prints: loaded coin (0.9, 0.1): 0.469 bits
print("fair eight-sided die:", round(H([1 / 8] * 8), 3), "bits")  # prints: fair eight-sided die: 3.0 bits
```

In words: the fair coin is the most uncertain two-outcome distribution, at one bit. The loaded coin is more predictable, at $0.469$ bits, because most flips are heads. The uniform die over eight faces has three bits, the same as three fair coins.

## Twenty questions

Entropy is the number of yes/no questions an optimal player needs on average. With eight equally likely objects, each question can split the candidates in half, so three questions always suffice. With the loaded coin, a good strategy asks about the likely outcome first, and the average number of questions falls below one bit per flip only when the guess can be made correct more often.

The check below computes the expected number of questions for the uniform eight-outcome case, which is exactly the entropy.

```python
import math

outcomes = list(range(8))
questions_needed = {x: 3 for x in outcomes}  # each outcome identified by 3 halving questions
expected = sum(questions_needed[x] / 8 for x in outcomes)
print("expected questions:", expected, " entropy:", round(H([1 / 8] * 8), 3))  # prints: expected questions: 3.0 entropy: 3.0
```

In words: the average number of questions matches the entropy exactly for this uniform case. For unequal probabilities, entropy is still the lower bound, and Huffman coding in a later note reaches it closely.

<Callout type="pitfall">
Entropy depends on the distribution, not on the labels. Two coins with the same bias have the same entropy whatever their faces are called, and an entropy value means nothing without saying which distribution it describes.
</Callout>

## Why it matters

Entropy bounds the best possible compression of data: no lossless code can use fewer bits per symbol, on average, than the entropy of the source. The later notes build on this: cross-entropy as a loss, KL divergence as a distance between distributions, and mutual information as shared uncertainty.

Some messages tell you more than others. Learning that a fair coin landed heads tells you one bit; learning that the sun rose tells you almost nothing. Shannon's entropy turns this into a number for a whole distribution: the average information you get from one outcome, measured in bits. It is the central quantity of information theory, and it sets the limit on how far data can be compressed. This note defines surprise and entropy, checks the fair and loaded coin, and connects entropy to the game of twenty questions.

## Surprise

An outcome with probability $p$ carries surprise $\log_2(1/p)$ bits. Using base 2 means the unit is the bit: one yes/no answer. A fair coin flip has $p = \frac{1}{2}$, so its surprise is exactly one bit. A one-in-eight event has surprise three bits.

```python
import math

for p in [1 / 2, 1 / 4, 1 / 8, 0.9]:
    print(f"p = {p:.3f}: surprise = {math.log2(1 / p):.3f} bits")
# p = 0.500: surprise = 1.000 bits
# p = 0.250: surprise = 2.000 bits
# p = 0.125: surprise = 3.000 bits
# p = 0.900: surprise = 0.152 bits
```

In words: halving the probability adds one bit. The likely outcome $0.9$ carries only $0.152$ bits, which is why common news is cheap to report.

## Entropy as average surprise

The entropy averages surprise over the distribution:

$$
H(p) = -\sum_x p(x)\log_2 p(x).
$$

The script below computes it for a fair coin, a loaded coin and a fair eight-sided die.

```python
import math

def H(ps):
    return -sum(p * math.log2(p) for p in ps if p > 0)

print("fair coin:", round(H([0.5, 0.5]), 3), "bits")
print("loaded coin (0.9, 0.1):", round(H([0.9, 0.1]), 3), "bits")
print("fair eight-sided die:", round(H([1 / 8] * 8), 3), "bits")
# fair coin: 1.0 bits
# loaded coin (0.9, 0.1): 0.469 bits
# fair eight-sided die: 3.0 bits
```

In words: the fair coin is the most uncertain two-outcome distribution, at one bit. The loaded coin is more predictable, at $0.469$ bits, because most flips are heads. The uniform die over eight faces has three bits, the same as three fair coins.

## Twenty questions

Entropy is a lower bound on the number of yes/no questions an optimal player needs on average, and the best strategy comes within one question of it. With eight equally likely objects, each question can split the candidates in half, so three questions always suffice, exactly the entropy. With a single loaded coin you still need one question per flip, even though the entropy is only $0.469$ bits; the average can approach the entropy only by asking about blocks of flips together.

The check below builds the best question strategy for an uneven distribution (a Huffman tree, covered in the [Coding Theory](../coding-theory/) note) and compares its average number of questions with the entropy.

```python
import heapq
import math

def H(ps):
    return -sum(p * math.log2(p) for p in ps if p > 0)

def questions(ps):
    # merge the two least likely groups; every outcome inside a merged group needs one more question
    heap = [(p, [i]) for i, p in enumerate(ps)]
    depth = [0] * len(ps)
    heapq.heapify(heap)
    while len(heap) > 1:
        p1, g1 = heapq.heappop(heap)
        p2, g2 = heapq.heappop(heap)
        for i in g1 + g2:
            depth[i] += 1
        heapq.heappush(heap, (p1 + p2, g1 + g2))
    return sum(p * d for p, d in zip(ps, depth))

for ps in ([1 / 8] * 8, [0.4, 0.3, 0.2, 0.1]):
    print(f"entropy {H(ps):.3f} bits, best average questions {questions(ps):.3f}")
# entropy 3.000 bits, best average questions 3.000
# entropy 1.846 bits, best average questions 1.900
```

In words: for eight equal outcomes the best strategy needs exactly $3$ questions, the entropy. For the uneven distribution it needs $1.9$ questions on average, a little above the entropy of $1.846$ bits and less than one question more, as the bound promises.

<Callout type="pitfall">
Entropy depends on the distribution, not on the labels. Two coins with the same bias have the same entropy whatever their faces are called, and an entropy value means nothing without saying which distribution it describes.
</Callout>

## Why it matters

Entropy bounds the best possible compression of data: no lossless code can use fewer bits per symbol, on average, than the entropy of the source. The later notes build on this: cross-entropy as a loss, KL divergence as a distance between distributions, and mutual information as shared uncertainty.

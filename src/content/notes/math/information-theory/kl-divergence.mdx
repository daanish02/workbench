[Cross-entropy](../cross-entropy/) says how many bits you waste when you use the wrong distribution. KL divergence isolates the waste: it is the cross-entropy minus the entropy you could never avoid anyway. It appears wherever one probability model is compared with another, from comparing a fitted model to data to measuring how much a variational approximation loses. This note defines the divergence, proves it is non-negative, and shows the asymmetry with a concrete pair of distributions.

## Definition

$$
D(p \,\|\, q) = \sum_x p(x)\log_2\frac{p(x)}{q(x)} = H(p, q) - H(p).
$$

Each term compares the true probability $p(x)$ with the believed probability $q(x)$ and weights the log-ratio by how often $x$ occurs. The script below computes it for two distributions over two outcomes.

```python
import math

p = [0.5, 0.5]
q = [0.9, 0.1]
D_pq = sum(a * math.log2(a / b) for a, b in zip(p, q))
print("D(p || q) =", round(D_pq, 4), "bits")  # prints: D(p || q) = 0.737 bits
```

In words: if the data are fair coin flips but you model them as a coin that lands heads $90\%$ of the time, you waste about $0.737$ bits per flip.

## Never negative

Gibbs' inequality says $D(p \,\|\, q) \ge 0$. The reason is that $\log$ is concave, so $\sum p \log(q/p) \le \log \sum q = 0$. The check below tests the inequality on random pairs of distributions over four outcomes.

```python
import math
import random

random.seed(5)

def normalise(v):
    s = sum(v)
    return [x / s for x in v]

ok = True
for _ in range(10000):
    p = normalise([random.random() + 1e-9 for _ in range(4)])
    q = normalise([random.random() + 1e-9 for _ in range(4)])
    if sum(a * math.log2(a / b) for a, b in zip(p, q)) < -1e-12:
        ok = False
print("KL divergence is never negative on 10000 random pairs:", ok)  # prints: KL divergence is never negative on 10000 random pairs: True
```

In words: no random pair produced a negative divergence, and the value is zero only when the two distributions coincide.

## Not symmetric

Swap the arguments and the answer changes. The divergence from $q$ to $p$ weights the log-ratio by $q$'s probabilities instead.

```python
import math

p = [0.5, 0.5]
q = [0.9, 0.1]
D_pq = sum(a * math.log2(a / b) for a, b in zip(p, q))
D_qp = sum(a * math.log2(a / b) for a, b in zip(q, p))
print("D(p || q) =", round(D_pq, 4), " D(q || p) =", round(D_qp, 4))  # prints: D(p || q) = 0.737 D(q || p) = 0.531
```

In words: $0.737$ and $0.531$ differ, so the direction matters. Which one is larger depends on the pair: swap the roles of the two distributions and the inequality flips. What does not change is what each direction punishes. $D(p \,\|\, q)$ weights by $p$, so it punishes $q$ for putting little mass where $p$ has a lot; fitting $q$ this way spreads it to cover everything $p$ does. $D(q \,\|\, p)$ weights by $q$, so it punishes $q$ for putting mass where $p$ has little; fitting this way makes $q$ settle on one region where $p$ is large.

<Callout type="pitfall">
A zero in $q$ where $p$ is positive makes $D(p \,\|\, q)$ infinite, while the reverse direction may be finite. A model that assigns zero probability to something that can happen will be infinitely wrong in this sense, so smoothing or mixing with a broader distribution is common practice.
</Callout>


## In a library

`scipy.stats.entropy` computes both entropy and KL divergence, and `scipy.special.rel_entr` gives the terms $p \log(p/q)$ with the conventions $0 \log 0 = 0$ and $p \log(p/0) = \infty$ built in:

```python
import numpy as np
from scipy.special import rel_entr
from scipy.stats import entropy

p, q = [0.5, 0.5], [0.9, 0.1]
print("D(p || q):", round(entropy(p, q, base=2), 4), " D(q || p):", round(entropy(q, p, base=2), 4))
print("zero in q where p > 0:", rel_entr([0.5, 0.5], [1.0, 0.0]).sum())
print("zero in p is fine:", round(rel_entr([1.0, 0.0], [0.5, 0.5]).sum() / np.log(2), 4))
# D(p || q): 0.737  D(q || p): 0.531
# zero in q where p > 0: inf
# zero in p is fine: 1.0
```

In words: the library reproduces $0.737$ and $0.531$ bits, returns infinity when $q$ rules out an outcome $p$ allows, and handles a zero in $p$ without error, the two cases of the pitfall above. Run it with `uv run --with numpy --with scipy`.

## Where it is used

Maximum likelihood fitting minimises $D(\text{data} \,\|\, \text{model})$, because the entropy of the data is fixed. Variational methods minimise $D(\text{approximation} \,\|\, \text{posterior})$. In both cases the asymmetry tells you which direction of error the method cares about.

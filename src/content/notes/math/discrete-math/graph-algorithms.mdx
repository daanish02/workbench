An algorithm that passes a few tests may still be wrong on the next input. For [graph algorithms](../../../cs/algorithms/graph-algorithms/) the reliable way to know is a proof, and the proofs follow one pattern: find an **invariant**, a statement about the algorithm's state that is true at the start, stays true after each step, and implies the answer is right when the loop ends. This note proves the three classics, breadth-first search, Dijkstra's algorithm and Kruskal's algorithm, and for each one shows the input that breaks it when an assumption is dropped. It uses the [Proof Techniques](../../foundations/proof-techniques/) of induction and contradiction, and the vocabulary of [Graph Theory Basics](../graph-theory-basics/).

## Breadth-first search finds hop distances

BFS keeps a queue. It starts with the source at distance $0$; each time it removes a vertex $u$, it gives every undiscovered neighbour the distance $d(u) + 1$ and adds it to the back of the queue.

**Invariant:** the queue holds vertices in non-decreasing order of assigned distance, and its first and last entries differ by at most $1$.

**Claim:** BFS assigns every reachable vertex its true hop distance $\delta(v)$, the fewest edges on any path from the source.

*Proof.* By induction on $k = \delta(v)$. For $k = 0$ the only such vertex is the source. Suppose every vertex with true distance $k$ received distance $k$. A vertex $v$ with $\delta(v) = k + 1$ has a neighbour $u$ with $\delta(u) = k$, on a shortest path. By the invariant, all distance-$k$ vertices leave the queue before any distance-$(k+1)$ vertex, so $v$ is discovered no later than when $u$ is processed, and it cannot be discovered earlier from a vertex at distance below $k$, since that would give $v$ a shorter path. So $v$ receives $k + 1$.

The script below runs BFS on a small graph and checks every distance against NetworkX's independent implementation.

```python
from collections import deque

import networkx as nx

adj = {0: [1, 2], 1: [0, 3], 2: [0, 3, 4], 3: [1, 2, 5], 4: [2, 5], 5: [3, 4]}

def bfs(src):
    dist = {src: 0}
    q = deque([src])
    while q:
        u = q.popleft()
        for v in adj[u]:
            if v not in dist:          # first discovery is along a shortest path
                dist[v] = dist[u] + 1
                q.append(v)
    return dist

G = nx.Graph((u, v) for u in adj for v in adj[u])
print("BFS distances:", bfs(0))
print("match NetworkX:", bfs(0) == nx.single_source_shortest_path_length(G, 0))
# BFS distances: {0: 0, 1: 1, 2: 1, 3: 2, 4: 2, 5: 3}
# match NetworkX: True
```

In words: the distances agree with the library on every vertex. The test is evidence; the induction is what makes it true for every graph. Run it with `uv run --with networkx`.

## Dijkstra's algorithm and the settled set

Dijkstra keeps a set $S$ of **settled** vertices whose distances are final. Each round it settles the unsettled vertex $u$ with the smallest tentative distance $d(u)$, then **relaxes** $u$'s edges: for each neighbour $v$, $d(v) \leftarrow \min(d(v), d(u) + w(u, v))$.

**Invariant:** for every settled vertex, $d(v)$ equals the true distance $\delta(v)$.

*Proof that settling $u$ keeps the invariant*, by contradiction. Suppose a path $P$ to $u$ is shorter than $d(u)$. $P$ starts inside $S$ and ends outside it, so it has a first vertex $y$ outside $S$, reached from some settled $x$. When $x$ was settled, relaxing its edge set $d(y) \le \delta(x) + w(x, y) = \delta(y)$. The rest of $P$, from $y$ to $u$, has **non-negative** weight, so $\delta(y) \le \text{length}(P) < d(u)$. Then $d(y) < d(u)$, and Dijkstra would have picked $y$ instead of $u$. Contradiction.

The step marked "non-negative" is the only place the weights matter, and removing it breaks the algorithm:

```python
import heapq

def dijkstra(adj, src):
    dist, settled = {src: 0}, set()
    pq = [(0, src)]
    while pq:
        d, u = heapq.heappop(pq)
        if u in settled:
            continue
        settled.add(u)                 # final, by the invariant
        for v, w in adj[u]:
            if v not in settled and d + w < dist.get(v, float("inf")):
                dist[v] = d + w
                heapq.heappush(pq, (d + w, v))
    return dist

good = {"A": [("B", 4), ("C", 1)], "B": [("D", 5)], "C": [("B", 2), ("D", 8)], "D": []}
bad = {"A": [("B", 2), ("C", 3)], "B": [], "C": [("B", -2)]}
print("non-negative weights:", dijkstra(good, "A"))
print("negative edge C->B:", dijkstra(bad, "A"), " but A->C->B costs", 3 - 2)
# non-negative weights: {'A': 0, 'B': 3, 'C': 1, 'D': 8}
# negative edge C->B: {'A': 0, 'B': 2, 'C': 3}  but A->C->B costs 1
```

In words: with non-negative weights the distances are right ($B$ is reached through $C$ for $3$). With the edge $C \to B$ of weight $-2$, Dijkstra settles $B$ at $2$ before it looks at $C$, and never revisits it, although the path through $C$ costs $1$. Bellman–Ford, which relaxes every edge $|V| - 1$ times instead of settling vertices, handles negative weights.

<Callout type="pitfall">
"It worked on my tests" is not a proof for Dijkstra. Negative weights only cause wrong answers when a cheaper path reaches an already-settled vertex, so random tests often pass. Check the assumption on the input instead: every weight must be at least zero.
</Callout>

## Minimum spanning trees and the cut property

A **cut** splits the vertices into two non-empty groups, and an edge **crosses** the cut when its ends lie in different groups.

**Cut property:** for any cut, a lightest edge crossing it belongs to some minimum spanning tree (MST).

*Proof*, by an exchange argument. Let $e$ be a lightest crossing edge and $T$ any MST. If $e \in T$ we are done. Otherwise adding $e$ to $T$ creates a cycle, and the cycle must cross the cut a second time, through some edge $f \in T$. Swapping gives $T' = T + e - f$, which is still a spanning tree, with weight $w(T) + w(e) - w(f) \le w(T)$ because $e$ was the lightest crossing edge. So $T'$ is an MST containing $e$.

**Kruskal is correct.** Kruskal scans edges from lightest to heaviest and keeps an edge when its ends are in different components of the edges kept so far. When it keeps $e = \{u, v\}$, take the cut that puts $u$'s current component on one side. No kept edge crosses it, and every lighter crossing edge would already have been kept, so $e$ is a lightest crossing edge, and by the cut property it belongs to an MST. Induction over the kept edges finishes the proof.

```python
import networkx as nx

edges = [(1, "A", "C"), (2, "B", "C"), (4, "A", "B"), (5, "B", "D"), (8, "C", "D")]
parent = {v: v for v in "ABCD"}

def find(v):                      # root of v's component in the union-find forest
    while parent[v] != v:
        v = parent[v]
    return v

tree = []
for w, u, v in sorted(edges):
    if find(u) != find(v):        # different components: e is the lightest edge across that cut
        parent[find(u)] = find(v)
        tree.append((u, v, w))

G = nx.Graph()
G.add_weighted_edges_from((u, v, w) for w, u, v in edges)
print("Kruskal:", tree, " weight", sum(w for *_, w in tree))
print("NetworkX MST weight:", nx.minimum_spanning_tree(G).size(weight="weight"))
# Kruskal: [('A', 'C', 1), ('B', 'C', 2), ('B', 'D', 5)]  weight 8
# NetworkX MST weight: 8.0
```

In words: Kruskal keeps the edges of weight $1$, $2$ and $5$. The weight-$4$ edge $A\text{–}B$ is skipped because $A$ and $B$ are already joined through $C$, so it would close a cycle, and the same happens to the weight-$8$ edge $C\text{–}D$. NetworkX finds a tree of the same weight, $8$.

## The pattern

Each proof above has the same three parts: an invariant, a step that preserves it, and an end condition that turns it into the answer. The same pattern proves loop correctness in general, which is why a [loop invariant](../../foundations/proof-techniques/) is the first thing to write down when an algorithm needs to be trusted.

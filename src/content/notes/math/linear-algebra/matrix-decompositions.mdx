Solving a linear system by elimination mixes the work of factoring the matrix with the work of solving for one right-hand side. Those are different jobs. Many problems have the same matrix with many right-hand sides, and in optimisation the matrix changes slowly. A matrix decomposition separates the two: factor the matrix once into simple pieces, then reuse the pieces. This note covers the three factorisations you will meet most often, and why each one exists.

## LU: elimination written down

Gaussian elimination, from the [Systems of Linear Equations](../systems-of-linear-equations/) note, can be recorded as a matrix factorisation. The $U$ factor is the upper triangular result of elimination, and $L$ is the lower triangular matrix of the multipliers used. So $A = LU$.

Once you have $L$ and $U$, solving $A\mathbf{x} = \mathbf{b}$ is two triangular solves. Solve $L\mathbf{y} = \mathbf{b}$ by forward substitution, then $U\mathbf{x} = \mathbf{y}$ by back substitution. Each costs about $n^2$ operations, far less than the $\frac{2}{3}n^3$ for the factorisation, so new right-hand sides are cheap.

The check below factors a $2 \times 2$ matrix by hand, then solves a system through the two triangular solves.

```python
import numpy as np
from scipy.linalg import solve_triangular

A = np.array([[4.0, 3.0],
              [6.0, 3.0]])

L = np.array([[1.0, 0.0],
              [A[1, 0] / A[0, 0], 1.0]])
U = np.array([[A[0, 0], A[0, 1]],
              [0.0, A[1, 1] - L[1, 0] * A[0, 1]]])
print("L U reproduces A:", np.allclose(L @ U, A))
print("U is upper triangular:", np.allclose(np.tril(U, -1), 0))

b = np.array([1.0, 2.0])
y = solve_triangular(L, b, lower=True)   # forward substitution, about n^2 work
x = solve_triangular(U, y)               # back substitution
print("solution via LU equals direct solve:", np.allclose(x, np.linalg.solve(A, b)))
# L U reproduces A: True
# U is upper triangular: True
# solution via LU equals direct solve: True
```

In words: the multiplier $\frac{6}{4} = 1.5$ sits in $L$, and $U$ holds the eliminated rows. The product $LU$ returns $A$, and the two triangular solves give the same answer as a direct solve. The factorisation is the same for any $\mathbf{b}$.

In practice the library factors once, with pivoting, and reuses the factors for every new right-hand side:

```python
import numpy as np
from scipy.linalg import lu, lu_factor, lu_solve

A = np.array([[4.0, 3.0], [6.0, 3.0]])
P, L, U = lu(A)                       # A = P L U; P records the row swap
print("pivoted L:", L.round(4).tolist(), " P swaps rows:", not np.allclose(P, np.eye(2)))  # prints: pivoted L: [[1.0, 0.0], [0.6667, 1.0]]  P swaps rows: True

factors = lu_factor(A)                # factor once
for b in ([1.0, 2.0], [0.0, 1.0]):    # then each solve is two cheap triangular passes
    print("solve for b =", b, "->", lu_solve(factors, b).round(4))
# solve for b = [1.0, 2.0] -> [ 0.5    -0.3333]
# solve for b = [0.0, 1.0] -> [ 0.5    -0.6667]
```

In words: SciPy swaps the rows so the larger entry $6$ is the pivot, which is the partial pivoting of the pitfall above, and the multiplier becomes $\frac{4}{6}$. After one factorisation, each new $\mathbf{b}$ costs only the two triangular solves. Run it with `uv run --with numpy --with scipy`.

<Callout type="pitfall">
LU without row swaps fails when a pivot is zero, and it can be unstable when a pivot is tiny. Libraries use partial pivoting, which records a permutation $P$ so that $PA = LU$. The idea is the same; the bookkeeping is longer.
</Callout>

## QR: stable least squares

A QR factorisation writes $A = QR$, with $Q$ having orthonormal columns and $R$ upper triangular. Orthogonal matrices do not amplify errors, so QR is the stable way to solve least-squares problems, as the [Projections](../projections/) note explained. The columns of $Q$ are what Gram-Schmidt produces from the columns of $A$, and $R$ records the coefficients of that process.

The check below factors a matrix into $Q$ and $R$ and confirms the orthogonality of $Q$ and the product.

```python
import numpy as np

A = np.array([[4.0, 3.0],
              [6.0, 3.0]])
Q, R = np.linalg.qr(A)
print("Q orthogonal:", np.allclose(Q.T @ Q, np.eye(2)), " Q R reproduces A:", np.allclose(Q @ R, A))
# Q orthogonal: True  Q R reproduces A: True
```

In words: $Q$ is orthogonal and $QR$ returns $A$. The same factorisation solves least squares without forming $A^\top A$, which avoids squaring the condition number.

## Cholesky: symmetric positive definite matrices

A symmetric matrix $S$ is **positive definite** when $\mathbf{x}^\top S\mathbf{x} > 0$ for every nonzero $\mathbf{x}$. Such matrices, which include covariance matrices, factor as $S = GG^\top$ with $G$ lower triangular. This Cholesky factorisation needs about half the work of LU, and it fails cleanly if the matrix is not positive definite, which is a useful test.

```python
import numpy as np

S = np.array([[4.0, 2.0],
              [2.0, 3.0]])
G = np.linalg.cholesky(S)
print("Cholesky factor G:\n", np.round(G, 4))
print("G G^T reproduces S:", np.allclose(G @ G.T, S))
# Cholesky factor G:
#  [[2.     0.    ]
#  [1.     1.4142]]
# G G^T reproduces S: True
```

In words: $G$ is lower triangular and $GG^\top$ returns $S$. Gaussian models and many optimisers use this factor to sample from or solve with a covariance matrix.

## Choosing a factorisation

Use LU for a general square system. Use QR for least squares and when stability matters most. Use Cholesky when the matrix is symmetric and positive definite. Use an SVD when the matrix may be singular or you need rank, as in the [Singular Value Decomposition](../singular-value-decomposition-svd/) note. The cost of solving a system is dominated by the factorisation, so choose the one whose structure matches your matrix.

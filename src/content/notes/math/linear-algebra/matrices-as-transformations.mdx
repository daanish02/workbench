A matrix looks like a table of numbers, but the more useful view is that it is a machine. Feed it a vector and it returns another vector. The rotations, reflections and stretches in the [Geometric Transformations](../../geometry/geometric-transformations/) note are all matrices, and so is the step that updates a neural network's weights. This note makes that view precise: what it means for a matrix to act on vectors, why the columns carry all the information, and how products of matrices describe sequences of transformations.

## A matrix acts on vectors

For a $2 \times 2$ matrix $A$ and a vector $\mathbf{x}$, the product $A\mathbf{x}$ is a new vector. Each entry of the result is a dot product of a row of $A$ with $\mathbf{x}$:

$$
A\mathbf{x} = \begin{pmatrix} a & b \\ c & d \end{pmatrix}\begin{pmatrix} x_1 \\ x_2 \end{pmatrix} = \begin{pmatrix} a x_1 + b x_2 \\ c x_1 + d x_2 \end{pmatrix}.
$$

The map $\mathbf{x} \mapsto A\mathbf{x}$ is **linear**, which means two rules hold for all vectors $\mathbf{x}, \mathbf{y}$ and scalars $c$:

- $A(\mathbf{x} + \mathbf{y}) = A\mathbf{x} + A\mathbf{y}$ (additivity)
- $A(c\mathbf{x}) = c\,A\mathbf{x}$ (homogeneity)

Linearity implies that the origin stays fixed and straight lines stay straight, with evenly spaced points staying evenly spaced.

The script below applies a $2 \times 2$ matrix to a vector, and checks both linearity rules on specific inputs.

```python
import numpy as np

A = np.array([[2.0, 1.0],
              [0.0, 3.0]])
x = np.array([1.0, 2.0])
y = np.array([-1.0, 0.5])

print("A x =", A @ x)  # prints: A x = [4. 6.]
print("linear in addition:", np.allclose(A @ (x + y), A @ x + A @ y))  # prints: linear in addition: True
print("linear in scaling:", np.allclose(A @ (3 * x), 3 * (A @ x)))  # prints: linear in scaling: True
```

In words: $A\mathbf{x} = (2 \cdot 1 + 1 \cdot 2,\ 0 \cdot 1 + 3 \cdot 2) = (4, 6)$. The two linearity checks both return `True`, which is what linearity says must happen. A check on a few inputs does not prove linearity in general, but for matrices the rule follows directly from the row-by-row definition of the product.

## The columns are the story

Read $A\mathbf{x}$ column by column instead of row by row. The product is a linear combination of the columns of $A$, weighted by the entries of $\mathbf{x}$:

$$
A\mathbf{x} = x_1\,\mathbf{a}_1 + x_2\,\mathbf{a}_2.
$$

This is the most useful view. The column $\mathbf{a}_1$ is where the first basis vector $\mathbf{e}_1$ lands, and $\mathbf{a}_2$ is where $\mathbf{e}_2$ lands. Every other point is a combination of those two, so knowing the two columns determines the entire transformation. A rotation by $90°$ has columns $(0, 1)$ and $(-1, 0)$: the first axis turns to point up, and the second turns to point left.

```python
import numpy as np

A = np.array([[2.0, 1.0],
              [0.0, 3.0]])
x = np.array([1.0, 2.0])

print("columns combined:", x[0] * A[:, 0] + x[1] * A[:, 1])  # prints: columns combined: [4. 6.]
```

In words: the same answer, $(4, 6)$, comes from weighting the columns $(2, 0)$ and $(1, 3)$ by $1$ and $2$. The column view is the one to keep, because it reveals what happens to the basis, which is everything about the transformation.

## Products are compositions

If $A$ and $B$ are matrices, the product $AB$ is the matrix that applies $B$ first and then $A$: $(AB)\mathbf{x} = A(B\mathbf{x})$. This is why matrix multiplication is defined the way it is. It is the rule that makes composition of linear maps come out right.

Matrix multiplication is **not commutative** in general. Applying a shear then a rotation is different from applying the rotation then the shear. The check below confirms both facts for a shear-like matrix $A$ and a $90°$ rotation $B$.

```python
import numpy as np

A = np.array([[2.0, 1.0],
              [0.0, 3.0]])
B = np.array([[0.0, -1.0],
              [1.0,  0.0]])  # rotation by 90 degrees
x = np.array([1.0, 2.0])

print("apply B then A equals (A B) x:", np.allclose(A @ (B @ x), (A @ B) @ x))  # prints: apply B then A equals (A B) x: True
print("order matters (A B != B A):", not np.allclose(A @ B, B @ A))  # prints: order matters (A B != B A): True
```

In words: `True` for the first line is the associativity of composition: doing $B$ then $A$ to $\mathbf{x}$ is the same as applying the single matrix $AB$. The second line says the two orders give different matrices, so the order of a sequence of transformations is part of its meaning.

## Identity and inverse

The **identity matrix** $I$ has ones on the diagonal and zeros elsewhere. It satisfies $I\mathbf{x} = \mathbf{x}$ for every $\mathbf{x}$, so it is the do-nothing transformation. The **inverse** $A^{-1}$, when it exists, satisfies $A^{-1}A = I$, so applying $A$ and then $A^{-1}$ returns every vector to where it started. Not every matrix has an inverse. A matrix that squashes the plane onto a line destroys information, and no map can undo that. The [Determinants](../determinants/) note gives the test.

<Callout type="pitfall">
A matrix written as $A\mathbf{x}$ acts on the column vector $\mathbf{x}$, and $\mathbf{x}A$ means something else (or nothing, if the shapes do not match). Keep the convention straight when reading code: many libraries store data as rows, which transposes everything.
</Callout>

## Why this matters

Almost every linear operation in computing is a matrix acting on vectors: image filters, the layers of a neural network, the rendering pipeline that places triangles on a screen. Thinking of a matrix as a transformation tells you what the operation does geometrically, and that is often enough to choose the right one.

Counting is the part of mathematics that most often hides an error. The number of ways to seat five people is a simple formula, but the number of ways to choose a committee with a rule about who must be included needs the same care as a proof. This note builds counting from one rule, the product rule, then adds order and repetition, and ends with the binomial theorem, which is counting applied to algebra. The [Sets](../sets/) note's inclusion–exclusion principle is the next tool to add.

## The product rule

If a task has two stages and the first has $m$ outcomes while the second has $n$ for each first outcome, the task has $m \cdot n$ outcomes. Three choices with 4, 3 and 2 options give $4 \cdot 3 \cdot 2 = 24$ ways.

The rule extends to any number of stages, and it is the foundation for everything below. When a count looks hard, break it into stages and multiply.

## Permutations and combinations

Two questions decide which formula applies. Does order matter? Are items used up?

- A **permutation** is an ordered selection of $k$ items from $n$ with no repeats: $P(n, k) = n! / (n - k)!$. The first item has $n$ choices, the second $n - 1$, and so on.
- A **combination** is an unordered selection of $k$ from $n$: $C(n, k) = n! / (k! (n - k)!)$. Each combination corresponds to $k!$ permutations, so we divide by $k!$.

The factorial $n!$ is $n \cdot (n - 1) \cdot ... \cdot 1$, with $0! = 1$. The script below checks both formulas against brute-force enumeration of small cases, using `math.comb` and `math.perm` for the formulas.

```python
from itertools import combinations, permutations
from math import comb, perm

print("5 choose 2 =", comb(5, 2), "list size:", len(list(combinations(range(5), 2))))  # prints: 5 choose 2 = 10 list size: 10
print("P(5,2) =", perm(5, 2), "list size:", len(list(permutations(range(5), 2))))  # prints: P(5,2) = 20 list size: 20
```

In words: choosing 2 of 5 ignoring order gives 10, and listing ordered pairs gives 20, which is $10 \cdot 2!$. Both enumerations agree with the formulas, so the formulas can be trusted for larger $n$ where listing is impossible.

## The four counting formulas

Allowing repetition adds two more cases. Choosing $k$ items from $n$ kinds with repeats allowed gives $n^k$ ordered results (each position has $n$ options) and $C(n + k - 1, k)$ unordered ones. The unordered count is the **stars and bars** argument: write the $k$ chosen items as stars and separate the $n$ kinds with $n - 1$ bars, so a selection is a choice of which $k$ of the $n + k - 1$ positions are stars.

| | Order matters | Order does not matter |
| --- | --- | --- |
| No repetition | $P(n, k) = \frac{n!}{(n - k)!}$ | $C(n, k) = \frac{n!}{k!(n - k)!}$ |
| Repetition allowed | $n^k$ | $C(n + k - 1, k)$ |

```python
from itertools import combinations_with_replacement, product
from math import comb

n, k = 4, 3
print("ordered with repeats:", len(list(product(range(n), repeat=k))), " formula n^k:", n ** k)  # prints: ordered with repeats: 64  formula n^k: 64
print("unordered with repeats:", len(list(combinations_with_replacement(range(n), k))), " formula C(n+k-1, k):", comb(n + k - 1, k))  # prints: unordered with repeats: 20  formula C(n+k-1, k): 20
```

In words: three scoops from four flavours give $64$ ordered sequences but only $20$ distinct cups when order is ignored, matching both formulas. Two questions, order and repetition, pick the row and column of the table.

## Repeated letters

When items repeat, the permutation formula overcounts, because swapping two identical items gives the same arrangement. Divide by the factorial of each repeated group. The letters of `MISSISSIPPI` have 11 positions with $M$ once, $I$ four times, $S$ four times and $P$ twice, so the number of arrangements is

$$
\frac{11!}{1! \cdot 4! \cdot 4! \cdot 2!} = 34650.

$$

The formula is the same as before with the repeated-letter factorials in the denominator, and it is a common source of mistakes in probability problems.

<Callout type="pitfall">
Counting a committee of two from $\{A, B, C\}$ as $P(3, 2) = 6$ double-counts, because $\{A, B\}$ and $\{B, A\}$ are the same committee. If the problem does not mention order, use $C(n, k)$.
</Callout>

## Pascal's triangle

Pascal's rule says that choosing $k$ from $n$ either includes a particular item (leaving $k - 1$ from the other $n - 1$) or excludes it (leaving $k$ from $n - 1$). So

$$
C(n, k) = C(n - 1, k - 1) + C(n - 1, k).

$$

Arranging the coefficients in rows, each entry is the sum of the two above it. Row 4 is $1, 4, 6, 4, 1$, the number of ways to choose 0, 1, 2, 3, or 4 items from 4. The check below confirms Pascal's rule over a range of $n$ and prints row 4.

```python
from math import comb

print("Pascal rule holds for n<=30:",
      all(comb(n, k) == comb(n - 1, k - 1) + comb(n - 1, k) for n in range(1, 31) for k in range(1, n)))  # prints: Pascal rule holds for n<=30: True
print("row 4 of Pascal's triangle:", [comb(4, k) for k in range(5)])  # prints: row 4 of Pascal's triangle: [1, 4, 6, 4, 1]
```

In words: the rule is true for every pair tested, and the row sums to 16, which is $2^{4}$ — the number of subsets of a 4-element set, as the [Sets](../sets/) note showed.

## The binomial theorem

Expanding $(x + y)^{n}$ multiplies out $n$ brackets. Each term picks either $x$ or $y$ from each bracket. A term with $k$ copies of $x$ arises from choosing which $k$ of the $n$ brackets contribute $x$, giving $C(n, k)$ ways. Hence

$$
(x + y)^{n} = \sum_{k=0}^{n} C(n, k)\, x^{k} y^{n-k}.

$$

The coefficients are row $n$ of Pascal's triangle. Setting $x = y = 1$ gives $2^{n} = \sum C(n, k)$, which counts the subsets again. The script below checks the expansion at specific values.

```python
from math import comb

x, y, n = 2, 3, 4
print("(x+y)^n =", (x + y) ** n,
      " sum C(n,k) x^k y^(n-k) =", sum(comb(n, k) * x**k * y**(n - k) for k in range(n + 1)))  # prints: (x+y)^n = 625 sum C(n,k) x^k y^(n-k) = 625
```

In words: $(2 + 3)^{4}$ is $625$, and summing the five weighted terms gives the same total, so the expansion is correct at these values. The same identity expands any power of a sum without multiplying out the brackets one by one.

## Counting in computing

Combinatorics sets the cost of brute-force search. A password of length 8 over 62 characters has $62^{8}$ possibilities, a permutation count with repetition. Hash collisions follow the birthday problem, a counting argument about pairs. Test-case generators and the dynamic programming in the [Algorithms](../../../cs/algorithms/dynamic-programming/) note both rely on counting paths and subsets quickly.

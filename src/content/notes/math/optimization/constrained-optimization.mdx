Real problems rarely let every variable take any value. A budget caps total spending, a probability must lie between $0$ and $1$, a physical length cannot be negative. Constrained optimisation keeps the objective and adds the rules the answer must obey. The task becomes finding the best point inside a region, and the best point is often on the edge of that region rather than at a smooth bottom. This note sets up the problem, works two examples, and checks them by brute-force search.

## The problem

We minimise $f(x)$ subject to constraints. Write them as equalities $g(x) = 0$ and inequalities $h(x) \le 0$. The feasible region is

$$
\mathcal{F} = \{x : g(x) = 0,\; h(x) \le 0\}.
$$

A point is a solution if it is in $\mathcal{F}$ and no other point in $\mathcal{F}$ has a smaller value of $f$.

## An equality constraint

Find the point on the line $x + y = 2$ closest to the origin, which means minimising $x^2 + y^2$. The feasible region is the line itself. Substituting $y = 2 - x$ turns the problem into a one-variable minimisation, and the script below confirms the answer by searching the line.

```python
best = min(((x / 1000, 2 - x / 1000) for x in range(-3000, 3001)), key=lambda p: p[0] ** 2 + p[1] ** 2)
print("closest point on x + y = 2:", best, " squared distance:", round(best[0] ** 2 + best[1] ** 2, 4))  # prints: closest point on x + y = 2: (1.0, 1.0) squared distance: 2.0
```

In words: the closest point is $(1, 1)$, and the squared distance is $2$. The line is the feasible region, and the minimum sits where the circle of radius $\sqrt 2$ just touches it.

## An inequality constraint

Now allow any point with $x + y \le 2$, and minimise $(x - 2)^2 + (y - 2)^2$, the squared distance to $(2, 2)$. The point $(2, 2)$ itself violates the constraint, so the solution must lie on the boundary $x + y = 2$, and it is the projection of $(2, 2)$ onto that line.

```python
feasible = [(x / 100, y / 100) for x in range(-400, 401, 4) for y in range(-400, 401, 4) if x / 100 + y / 100 <= 2]
best = min(feasible, key=lambda p: (p[0] - 2) ** 2 + (p[1] - 2) ** 2)
print("best feasible point:", best, " value:", round((best[0] - 2) ** 2 + (best[1] - 2) ** 2, 4))  # prints: best feasible point: (1.0, 1.0) value: 2.0
print("unconstrained point (2, 2) feasible?", 2 + 2 <= 2)  # prints: unconstrained point (2, 2) feasible? False
```

In words: the search lands on $(1, 1)$, the constraint is active there, and the value is $2$. The unconstrained minimum $(2, 2)$ is not allowed, so the constraint decides the answer.

<Callout type="pitfall">
Checking that a point satisfies the constraints is part of the answer. Grid search only finds the best grid point, so a boundary solution like $(1, 1)$ is found only if the grid contains it. Continuous methods, or a known closed form, avoid that dependence.
</Callout>

## Projection onto a half-plane

For a single linear constraint $\mathbf{a}^\top \mathbf{x} \le b$ the nearest feasible point has a closed form: if $\mathbf{p}$ already satisfies it, keep it; otherwise move straight back along the normal $\mathbf{a}$ until it lands on the boundary,

$$
\operatorname{proj}(\mathbf{p}) = \mathbf{p} - \frac{\max(0,\ \mathbf{a}^\top \mathbf{p} - b)}{\|\mathbf{a}\|^2}\,\mathbf{a}.

$$

**Projected gradient descent** alternates an ordinary gradient step with this projection, which is the simplest way to keep iterates feasible.

```python
import numpy as np

a, b = np.array([1.0, 1.0]), 2.0
proj = lambda p: p - max(0.0, a @ p - b) / (a @ a) * a
print("projection of (2, 2):", proj(np.array([2.0, 2.0])), " of (0, 1):", proj(np.array([0.0, 1.0])))

x = np.array([-1.0, 0.0])
for _ in range(50):                     # minimise (x - 2)^2 + (y - 2)^2 subject to x + y <= 2
    x = proj(x - 0.2 * 2 * (x - 2.0))
print("projected gradient descent ends at:", x.round(4))
# projection of (2, 2): [1. 1.]  of (0, 1): [0. 1.]
# projected gradient descent ends at: [1. 1.]
```

In words: $(2, 2)$ violates the constraint and moves to $(1, 1)$ on the boundary, while $(0, 1)$ is already feasible and stays. Projected gradient descent from $(-1, 0)$ settles at $(1, 1)$, the answer the grid search found.

## Penalties and library solvers

A **penalty method** replaces the constraint with a cost for violating it, such as $\mu \max(0, x + y - 2)^2$, and minimises the result without constraints. The minimiser approaches the true solution as $\mu$ grows, which is why a penalty gives an approximate answer for any finite weight. Library solvers such as SLSQP handle the constraints exactly:

```python
import numpy as np
from scipy.optimize import minimize

f = lambda p: (p[0] - 2) ** 2 + (p[1] - 2) ** 2
for mu in (1.0, 10.0, 1000.0):
    res = minimize(lambda p: f(p) + mu * max(0.0, p[0] + p[1] - 2) ** 2, x0=[0.0, 0.0])
    print(f"penalty mu = {mu:>6}: minimiser {res.x.round(4)}")
res = minimize(f, x0=[0.0, 0.0], method="SLSQP", constraints=[{"type": "ineq", "fun": lambda p: 2 - p[0] - p[1]}])
print("SLSQP with the constraint:", res.x.round(4))
# penalty mu =    1.0: minimiser [1.3333 1.3333]
# penalty mu =   10.0: minimiser [1.0476 1.0476]
# penalty mu = 1000.0: minimiser [1.0005 1.0005]
# SLSQP with the constraint: [1. 1.]
```

In words: with weight $1$ the penalty solution sits well outside the region, at about $(1.33, 1.33)$; with weight $1000$ it is within a thousandth of $(1, 1)$. SLSQP, given the constraint directly (SciPy's `"ineq"` means the function must stay non-negative), returns $(1, 1)$. Run it with `uv run --with numpy --with scipy`.

## Active and inactive constraints

At the solution, each inequality is either active ($h(x) = 0$) or inactive ($h(x) < 0$). Inactive constraints can be dropped locally, since small moves do not reach them, so the problem reduces to an equality-constrained one. Identifying the active set is most of the work in small problems, and the [Lagrange multipliers](../lagrange-multipliers/) note shows how the active constraints determine the solution.

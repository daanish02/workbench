Many planning problems have a linear objective and linear limits: maximise profit given machine hours, minimise cost given nutrition requirements, route flow through a network. Linear programming solves these exactly and quickly, even with thousands of variables. The geometry is what makes it work. The feasible region is a flat-faced shape, and the best value is always reached at one of its corners. This note sets up a small problem, finds its vertices, and explains how the simplex method moves between them.

## The geometry

Consider maximising $3x + 2y$ subject to

$$
x + y \le 4, \qquad x + 3y \le 6, \qquad x \ge 0,\; y \ge 0.
$$

The feasible region is a polygon whose corners are the **vertices**. A linear function is constant along lines of equal value, so on a convex polygon its maximum over the region is attained at a corner. A vertex is the intersection of enough constraint boundaries to fix the point.

## Finding vertices by enumeration

For two variables, each vertex comes from solving two of the boundary lines together. The script below tries every pair of boundaries, keeps the intersections that are feasible, and takes the best objective value.

```python
from itertools import combinations

# each constraint as (a, b, c) meaning a*x + b*y <= c; x >= 0 and y >= 0 included as -x <= 0, -y <= 0
cons = [(1, 1, 4), (1, 3, 6), (-1, 0, 0), (0, -1, 0)]

def intersect(c1, c2):
    a1, b1, d1 = c1
    a2, b2, d2 = c2
    det = a1 * b2 - a2 * b1
    if abs(det) < 1e-12:
        return None
    return ((d1 * b2 - d2 * b1) / det, (a1 * d2 - a2 * d1) / det)

def feasible(p):
    return all(a * p[0] + b * p[1] <= c + 1e-9 for a, b, c in cons)

verts = set()
for c1, c2 in combinations(cons, 2):
    p = intersect(c1, c2)
    if p and feasible(p):
        verts.add((round(p[0], 6) + 0.0, round(p[1], 6) + 0.0))
print("vertices:", sorted(verts))
values = {v: 3 * v[0] + 2 * v[1] for v in verts}
best = max(values, key=values.get)
print("best vertex:", best, " objective:", values[best])
# vertices: [(0.0, 0.0), (0.0, 2.0), (3.0, 1.0), (4.0, 0.0)]
# best vertex: (4.0, 0.0)  objective: 12.0
```

In words: the four corners are $(0, 0)$, $(4, 0)$, $(3, 1)$ and $(0, 2)$. The objective values are $0$, $12$, $11$ and $4$, so the optimum is $(4, 0)$ with value $12$.

A library solver gives the same answer from the constraint matrix alone. `scipy.optimize.linprog` minimises, so the objective is negated:

```python
from scipy.optimize import linprog

res = linprog(c=[-3, -2], A_ub=[[1, 1], [1, 3]], b_ub=[4, 6], bounds=[(0, None), (0, None)], method="highs")
print("optimum:", res.x, " value:", -res.fun, " status:", res.message)
# optimum: [4. 0.]  value: 12.0  status: Optimization terminated successfully. (HiGHS Status 7: Optimal)
```

In words: the HiGHS solver behind `linprog` returns the vertex $(4, 0)$ and the value $12$, matching the enumeration. Run it with `uv run --with scipy`.

## The simplex method

Enumerating vertices works for two variables, but the number of vertices can grow exponentially in general. The simplex method avoids enumeration by starting at a vertex and moving along an edge to a neighbouring vertex with a better objective. When no neighbour improves the objective, the current vertex is optimal, and the convexity of the region guarantees it.

In the example, starting at the origin, the method moves along the $x$-axis to $(4, 0)$, where the objective is $12$. From there the edge toward $(3, 1)$ is worse, so the method stops. The checks above confirm this is the optimum.

<Callout type="pitfall">
A linear program can be infeasible, with no point satisfying every constraint, or unbounded, with the objective growing without limit. Simplex detects both cases, but a formulation error often produces one of them. Check the constraints on a known feasible point before trusting a solution.
</Callout>

## Why it matters

Linear programs are the building blocks of much larger methods: the relaxations used in integer programming, the flow problems in networks, and the subproblems in many learning algorithms. [Duality](../duality/), in the next note, gives each constraint a price, which is why solvers also report sensitivity.

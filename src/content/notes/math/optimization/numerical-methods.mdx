Most optimisation methods are iterations that refine a guess, and the question is how fast the guess improves. Newton's method is the fastest common iteration when the function is smooth and the starting point is close enough. Its speed is the reason it appears inside many libraries. Computers do not do exact arithmetic, though, and a method that is correct on paper can fail silently in code. This note covers Newton's method for square roots and minima, checks its convergence, and shows one floating-point trap.

## Newton's method for roots

To solve $f(x) = 0$, replace $f$ near the current guess by its tangent line and go to where the tangent crosses zero:

$$
x_{k+1} = x_k - \frac{f(x_k)}{f'(x_k)}.
$$

For $\sqrt 2$ take $f(x) = x^2 - 2$, so the update is $x \leftarrow \frac{1}{2}\left(x + \frac{2}{x}\right)$, the Babylonian method. The script below prints the error at each step.

```python
import math

x = 1.0
target = math.sqrt(2)
for k in range(1, 6):
    x = 0.5 * (x + 2 / x)
    print(f"step {k}: x = {x:.12f}, error = {abs(x - target):.2e}")  # prints: step 1: x = 1.500000000000, error = 8.58e-02
```

In words: the error goes from $0.086$ to about $2 \times 10^{-3}$ and then to about $2 \times 10^{-6}$. Each step roughly squares the error, which is quadratic convergence. The number of correct digits doubles each step.

## Comparison with bisection

Bisection halves the interval containing the root, so it gains one binary digit per step. The check below counts the steps each method needs to reach error below $10^{-10}$.

```python
import math

target = math.sqrt(2)
lo, hi, bis = 1.0, 2.0, 0
while hi - lo > 1e-10:
    mid = (lo + hi) / 2
    if mid * mid < 2:
        lo = mid
    else:
        hi = mid
    bis += 1
x, newt = 1.0, 0
while abs(x - target) > 1e-10:
    x = 0.5 * (x + 2 / x)
    newt += 1
print("bisection steps:", bis, " Newton steps:", newt)  # prints: bisection steps: 34 Newton steps: 4
```

In words: bisection needs $34$ steps and Newton's method needs $4$. Newton is much faster, but it needs the derivative and a starting point near the root.

## Newton's method for minima

To minimise $f$, find a zero of its gradient. In one dimension this is $x \leftarrow x - f'(x)/f''(x)$. The method finds the minimum of $f(x) = x^4 - 3x^2$ near $x = 2$ in a few steps, since the curvature there is positive.

```python
f1 = lambda x: 4 * x ** 3 - 6 * x
f2 = lambda x: 12 * x ** 2 - 6
x = 2.0
for k in range(1, 5):
    x = x - f1(x) / f2(x)
print("minimiser after 4 Newton steps:", round(x, 6), " exact sqrt(1.5) =", round(math.sqrt(1.5), 6))  # prints: minimiser after 4 Newton steps: 1.224779 exact sqrt(1.5) = 1.224745
```

In words: four steps reach $1.224779$, within $3 \times 10^{-5}$ of the exact minimiser $\sqrt{1.5} = 1.224745$. The update needs the second derivative, which is the cost of the speed.

## Floating-point trap

A computer stores numbers with about sixteen significant digits. Subtracting two numbers that are nearly equal keeps only the digits where they differ, which can be almost none. The script compares a naive and a rearranged computation of $\sqrt{x + 1} - \sqrt{x}$ for large $x$.

```python
import math

x = 1e16
naive = math.sqrt(x + 1) - math.sqrt(x)
stable = 1 / (math.sqrt(x + 1) + math.sqrt(x))
print("naive:", naive, " stable:", stable)  # prints: naive: 0.0 stable: 5e-09
```

In words: the exact value is about $5 \times 10^{-9}$. The naive subtraction returns $0$, because $x + 1$ is not representable next to $x = 10^{16}$, so both square roots are equal and the difference is lost entirely. The rearranged form avoids the subtraction and returns $5 \times 10^{-9}$.

<Callout type="pitfall">
Newton's method can fail silently. A poor starting point can send it far away, a zero derivative stops the update, and a nearly flat function gives huge steps. Check that the iterates converge and that the gradient is small at the answer, rather than trusting the last printed value.
</Callout>

## Why it matters

Every solver in optimisation rests on these ideas: iterate, measure the error, and watch for rounding. Quasi-Newton methods approximate the Hessian to avoid computing it, and the next note shows where smooth methods stop being enough.

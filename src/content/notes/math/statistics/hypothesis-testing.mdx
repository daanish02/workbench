A hypothesis test answers a yes-or-no question from noisy data: is this coin biased, does this drug work, did the page redesign change clicks? The method sets up a null hypothesis that describes no effect, measures how surprising the data are under it, and decides whether to reject it. The decision can be wrong in two ways, and the test is designed around controlling one of them. This note builds a test for a coin, states the error types, and checks the probabilities by simulation.

## The setup

Suppose we flip a coin $100$ times and see $60$ heads. Let $p$ be the chance of heads. The null hypothesis is $H_0: p = 0.5$, a fair coin, and the alternative is $H_1: p \ne 0.5$. Under $H_0$ the number of heads $X$ is binomial with mean $50$ and standard deviation $5$, and the normal approximation gives a test statistic

$$
z = \frac{\hat p - 0.5}{\sqrt{0.5 \cdot 0.5 / n}}, \qquad \hat p = \frac{X}{n}.
$$

For our data $\hat p = 0.6$ and $z = \frac{0.1}{0.05} = 2$.

## The p-value

The two-sided p-value is the probability, under $H_0$, of a $z$ at least as far from $0$ as $2$.

```python
import math

def Phi(x):
    return 0.5 * (1 + math.erf(x / math.sqrt(2)))

z = (0.6 - 0.5) / math.sqrt(0.5 * 0.5 / 100)
p_value = 2 * (1 - Phi(abs(z)))
print("z =", round(z, 3), " two-sided p-value =", round(p_value, 4))
# z = 2.0  two-sided p-value = 0.0455
```

In words: by the normal approximation, a result at least this far from $50$ heads would occur about $4.6\%$ of the time if the coin were fair. That is not the probability that the coin is fair: the p-value is a statement about the data given the hypothesis, never the reverse.

The approximation matters here because the answer sits right at the usual $0.05$ cut-off. The exact binomial test counts the tail directly:

```python
from math import comb

n, k = 100, 60
tail = sum(comb(n, j) for j in range(k, n + 1)) / 2 ** n   # P(X >= 60) for a fair coin
print("exact two-sided p-value:", round(2 * tail, 4))
# exact two-sided p-value: 0.0569
```

In words: the exact p-value is $0.0569$, just above $0.05$, while the normal approximation gave $0.0455$, just below. The approximation treats the count as continuous; adding the continuity correction, $z = (59.5 - 50)/5 = 1.9$, gives $0.0574$ and agrees with the exact test. In a library this is one call, `scipy.stats.binomtest(60, 100).pvalue`. Near a cut-off, use the exact test, and treat $60$ heads in $100$ as borderline rather than as clear evidence.

## Type I error and the significance level

Choosing $\alpha = 0.05$ means we reject $H_0$ when the p-value is below $0.05$. If $H_0$ is true, this rejects about $5\%$ of the time, the Type I error rate. A simulation with a fair coin confirms it.

```python
import math
import random

random.seed(4)
trials, rejections = 20000, 0
for _ in range(trials):
    heads = sum(1 for _ in range(100) if random.random() < 0.5)
    z = (heads / 100 - 0.5) / math.sqrt(0.25 / 100)
    if abs(z) > 1.96:
        rejections += 1
print("share of fair-coin tests rejected at alpha = 0.05:", round(rejections / trials, 3))
# share of fair-coin tests rejected at alpha = 0.05: 0.057
```

In words: about $5.7\%$ of tests reject a true null, close to the target $5\%$. It sits a little above because a binomial count takes whole-number values and the normal cutoff is only an approximation. The significance level is a promise about this rate, and it says nothing about how often the alternative is true.

## Type II error and power

If the coin really has $p = 0.6$, a test with $n = 100$ rejects only some of the time. The power is the probability of rejection under that alternative. The normal approximation gives it directly.

```python
import math

def Phi(x):
    return 0.5 * (1 + math.erf(x / math.sqrt(2)))

p1, n = 0.6, 100
se0 = math.sqrt(0.25 / n)
se1 = math.sqrt(p1 * (1 - p1) / n)
crit = 1.96 * se0
power = (1 - Phi((0.5 + crit - p1) / se1)) + Phi((0.5 - crit - p1) / se1)
print("power at p = 0.6, n = 100:", round(power, 3))
# power at p = 0.6, n = 100: 0.516
```

In words: the test would miss a real $60\%$ coin about half the time with $100$ flips. Doubling the sample size would raise the power substantially, which is why planning a study starts from the effect size you need to detect.

<Callout type="pitfall">
A large p-value is not evidence that $H_0$ is true. It means the data did not reject $H_0$, which may simply reflect low power. Say 'we did not find evidence of an effect' rather than 'there is no effect'.
</Callout>

## Reading the trade-off

Lowering $\alpha$ reduces Type I errors and increases Type II errors, for a fixed sample size. The only way to reduce both is more data. Choose $\alpha$ based on how costly a false alarm is, and check power before collecting data, not after. For $n = 200$ flips the power against $p = 0.6$ rises from about $0.52$ to about $0.81$.

## Comparing two groups: the t-test

Most real tests compare two samples, such as page load times before and after a change, with an unknown spread. The **two-sample t-test** standardises the difference of means by its estimated standard error and compares it with a $t$ distribution rather than the normal; Welch's version does not assume the two groups have equal variances.

```python
import numpy as np
from scipy import stats

rng = np.random.default_rng(5)
before = rng.normal(200, 30, size=100)  # load times in ms
after = rng.normal(185, 30, size=100)
res = stats.ttest_ind(before, after, equal_var=False)   # Welch's t-test
print(f"means {before.mean():.1f} vs {after.mean():.1f}, t = {res.statistic:.2f}, p = {res.pvalue:.4f}")
# means 193.3 vs 187.8, t = 1.35, p = 0.1790
```

In words: the test reports how many standard errors apart the two means are, $1.35$ here, and how surprising that gap would be if the change did nothing. The true improvement in this simulation is $15$ ms, yet the samples differ by only about $5.5$ ms and $p = 0.18$: with this much noise, $100$ measurements per group are not enough to detect it reliably. That is low power, not evidence of no effect, as the pitfall above warns. Run it with `uv run --with numpy --with scipy`; the [A/B Testing](../../../ml/ml-systems/a-b-testing-for-ml/) note applies the same machinery to experiments.

## Many tests at once

Run twenty independent tests at $\alpha = 0.05$ when every null is true, and the chance of at least one false positive is $1 - 0.95^{20} \approx 0.64$. Testing many hypotheses, many metrics or many subgroups makes a "significant" result likely by chance alone. Two standard fixes:

- **Bonferroni:** test each at $\alpha / m$ for $m$ tests. It controls the chance of any false positive, and is conservative.
- **Benjamini–Hochberg:** sort the p-values and reject the $k$ smallest, where $k$ is the largest index with $p_{(k)} \le \frac{k}{m}\alpha$. It controls the **false discovery rate**, the expected share of rejections that are wrong, and keeps more power.

```python
import numpy as np
from scipy import stats

rng = np.random.default_rng(6)
m, alpha = 100, 0.05
is_real = np.arange(m) < 10                          # 10 real effects, 90 true nulls
z = rng.normal(np.where(is_real, 3.0, 0.0))
p = 2 * stats.norm.sf(np.abs(z))
naive = p < alpha
bonf = p < alpha / m
order = np.argsort(p)
passed = p[order] <= alpha * np.arange(1, m + 1) / m
k = passed.nonzero()[0].max() + 1 if passed.any() else 0
bh = np.zeros(m, bool)
bh[order[:k]] = True
for name, rej in [("no correction", naive), ("Bonferroni", bonf), ("Benjamini-Hochberg", bh)]:
    print(f"{name:>18}: {rej.sum():>2} rejected, {(rej & ~is_real).sum()} false, {(rej & is_real).sum()} of 10 real found")
#      no correction: 10 rejected, 1 false, 9 of 10 real found
#         Bonferroni:  7 rejected, 0 false, 7 of 10 real found
# Benjamini-Hochberg:  9 rejected, 0 false, 9 of 10 real found
```

In words: without a correction about $0.05 \times 90 \approx 4.5$ of the ninety true nulls are expected to come out significant; this run produced one false positive among ten rejections. Bonferroni removes the false positives but misses some real effects; Benjamini–Hochberg finds more of the real effects while keeping false discoveries rare. Deciding the tests in advance, and reporting how many were run, matters as much as the correction.
